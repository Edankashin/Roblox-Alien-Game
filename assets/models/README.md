# Models

Exported meshes for Studio import, one folder per species or prop. Keep 1 unit = 1 stud and aliens 2 to 3.5 units tall (B45). Nothing here is loaded by Rojo; Studio imports it through File → Import 3D or `tools/studio/install_models.luau`.

**The 35 species are block-cell models** (Decision B46, "Then finalize", 2026-10-21), exported by `tools/blocky/export_models.py` from the spec notes in `docs/vault/07-alien-game/Creatures/` through `tools/blender/blocky_build.py`. Each folder holds:

- `<Id>.glb` and `<Id>.fbx`: the same model, Y up, facing -Z (Roblox's front) with its right on +X, origin at the bottom centre of its bounds (`Config.ModelFacesPlusZ` stays false). One mesh a MeshPart, one material each: `Body` (every static cell block merged), `Glow` (static glow blocks, Neon), each moving part named as in `src/shared/data/Rigs.luau` with its origin on its pivot, and `FacePlate`. The FBX embeds its textures.
- `<Id>_atlas.png` (the block-cell atlas, nearest filtering: a SurfaceAppearance ColorMap with `ResampleMode = Pixelated` in Studio) and `<Id>_face.png` (the face plate's flipbook, frames left to right, four a row, the layout of the Rigs row's `face`).
- `materials.json`: one entry a MeshPart in GLB order with the same keys as before (`slot`, `name`, `hex`, `roughness`, `metallic`, `emission`; emission > 0 is Neon) plus `colorMap` (the PNG it samples), `pixelated` and on the plate `alphaMode`. No Surface-pass fields: the cell atlas is the surface.
- `notes.md` (tool, spec note, height, blocks, triangles, parts, eye key, frames) and the 256 px previews `<Id>.png` and `<Id>_grey.png`.

Regenerate with `$BPY tools/blocky/export_models.py --all` (or `--species A,B`; `$BPY` is a Python with the `bpy` module); `python3 -I tools/blocky/export_models.py --check` verifies every folder against its note and Rigs.luau without Blender (tested in `tools/tests/test_blocky_export.py`), and `--emit-luau` prints the installer's BLOCK_CELL table. The retired blockouts' heights and slots live on only as `tools/tests/fixtures/blockout_reference.json`, for the tests of the retired V2 recipes. Nothing is uploaded (B27): `asset_ids.json` keeps each species' old blockout id with a `pendingUpload` marker naming the new files until Ethan runs `python3 tools/upload_assets.py --redo --only <Ids>`, so the game keeps the old mesh (which World.RigAnimator leaves alone) until then.

Prop folders still hold `materials.json` in the old form, the material slots in MeshPart order, because an Open Cloud upload keeps one MeshPart per slot but drops the colours; `python3 tools/blender/materials_json.py --all` rebuilds it from the existing GLBs without touching a mesh.

`assets/models/props/<Name>/` holds the 16 scenery and camp props (trees, rocks, shrine stone, pedestal, geyser cone, ship hull, the three stations, the heater lamp), generated by `tools/blender/props_base.py` in the same format as the species (GLB, FBX, `notes.md`, one mesh with a material slot per colour) at 40 to 600 triangles each, standing on z = 0 with the pivot at the bottom centre. Studio imports them into `ReplicatedStorage.Models.Props.<Name>` by hand and the game falls back to part placeholders for any that are missing; regenerate with `python3 tools/blender/props_base.py --all`. See `docs/vault/06-art-pipelines/Map-Dressing.md` for the import and dressing workflow.

Bulk import: instead of File → Import 3D one file at a time, `python3 tools/upload_assets.py` uploads every `.glb` (or `.fbx` with `--format fbx`) here (32 species and 16 props) through the Open Cloud Assets API and records the asset ids in `assets/models/asset_ids.json` (a map of name to assetId, uploadedAt and file; safe to commit, it holds no key), and `tools/studio/install_models.luau` then places them under `ReplicatedStorage.Models` and `ReplicatedStorage.Models.Props` in Studio. The API key comes from the `ROBLOX_OPEN_CLOUD_KEY` environment variable and never lives in the repo; the Dashboard steps, commands and moderation delay are in `docs/vault/06-art-pipelines/Map-Dressing.md`, section "Bulk import through Open Cloud".
