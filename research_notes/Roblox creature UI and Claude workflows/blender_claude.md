## KQ1. What is the most reliable 2026 workflow from a written creature concept to a seamless cute low-poly creature in Roblox, with Claude, Blender and no artist, and where does each tool break?

### Takeaway
The only route that is fully scriptable, free, and under version control is the one this repo already runs: a written recipe per species, headless `bpy` (or the Blender MCP for a live look) building one fused skin (metaballs or voxel remesh), decimate or QuadriFlow to budget, materials restored from data after a GLB upload through Open Cloud. Every public 2026 "Claude + Blender for Roblox" project found on GitHub either stops at props and animation or depends on a local NVIDIA GPU; nobody publishes a working cute-creature pipeline. The breaks are consistent across sources: sculpt brush strokes cannot be driven headless or through any MCP, generated meshes arrive at arbitrary scale and facing with 100k+ triangles, a GLB upload drops colours unless they are restored from data, and animation needs a separate route (Studio's Animation Editor, a Blender-to-Roblox animation plugin, or an FBX with rig and keyframes through the Importer).

### Cited Findings

**The Blender MCP as it is in October 2026**
- The project is now published as `mcp-for-blender` (formerly `blender-mcp`); `uvx blender-mcp` still runs; Blender 3.0+, Python 3.10+, uv required; Claude Code is added with `claude mcp add blender uvx mcp-for-blender`; one-line installers exist for macOS/Linux and Windows; multiple instances need `--port` — [ahujasid README](https://raw.githubusercontent.com/ahujasid/blender-mcp/main/README.md)
- The repo `ahujasid/mcp-for-blender` has 30,866 stars and was pushed 2026-10-06 (MIT) — [GitHub search API](https://api.github.com/search/repositories?q=blender+mcp&sort=stars&per_page=20)
- Nine tools: `execute_blender_code`, `look`, `get_scene_info`, `generate_3d`, `search_assets`, `import_asset`, `get_addon_status`, `disable_telemetry`, `record_trajectory_feedback` — [README](https://raw.githubusercontent.com/ahujasid/blender-mcp/main/README.md)
- `look` modes: `viewport` (default), `camera`, `angles` ("the target from several sides, auto-framed; default front, right, top, three_quarter", up to six views), `frames` (a strip over the animation, 2 to 12 samples); shading `solid, material, rendered (EEVEE and Workbench only), wireframe, xray`; `max_size` default 768 px, clamped 200 to 2000; "Every setting changed to take the picture is restored afterwards" — [server.py](https://raw.githubusercontent.com/ahujasid/mcp-for-blender/main/src/blender_mcp/server.py)
- `generate_3d`: "Make one new textured 3D model from a text prompt or an image, and import it"; "One object per call: not a whole scene, the ground, or parts to assemble"; "Each call can cost the user money or a monthly generation"; waits up to 45 s then hands back a job handle, "Generation usually takes 1-3 minutes"; `provider` auto/tripo/hunyuan3d/hyper3d ("Auto prefers the user's MCP for Blender Premium generators, then their own API keys"); `quality` "standard" or "high" (Premium); `bbox_condition` hyper3d only; "It arrives at arbitrary scale and facing" — [server.py](https://raw.githubusercontent.com/ahujasid/mcp-for-blender/main/src/blender_mcp/server.py)
- Images attached in chat cannot be passed to `generate_3d`: "ask the user for a path or URL, don't fall back to text without asking" — [server.py](https://raw.githubusercontent.com/ahujasid/mcp-for-blender/main/src/blender_mcp/server.py)
- Safe mode `BLENDER_MCP_SAFE_MODE=1` blocks file, process and network access from scripts; the socket "has no authentication or encryption"; "ALWAYS save your work before using" `execute_blender_code`; Poly Haven downloads run on Blender's main thread and can freeze the UI; headless is mentioned only for injecting credentials in "headless setups or CI", not as a feature — [README](https://raw.githubusercontent.com/ahujasid/blender-mcp/main/README.md)
- The server's own operating rules for scripts run in someone else's Blender: look shader nodes up by type (names are localised), never hardcode enum identifiers, `scene.render.engine` under-reports, material colours go on shader node inputs — MCP for Blender server instructions as delivered to this session (primary, not a web page)
- Asset libraries: Poly Haven about 2,400 CC0 HDRIs, textures and models with no key; Sketchfab needs a key; Poly Pizza about 10,600 low-poly models, free key, about 69% CC-BY (filter `licence="CC0"`) — [README](https://raw.githubusercontent.com/ahujasid/blender-mcp/main/README.md)

- The Roblox animation skill "Requires one interactive, GUI-based Blender session. It refuses background Blender" — [animate-roblox-characters](https://raw.githubusercontent.com/dillydog580/animate-roblox-characters/main/README.md)

**The fused-skin route this repo tested (first-hand, headless `bpy` 5.0.1)**
- Metaballs to mesh, light Smooth, Decimate: 17,984 raw to 2,000 triangles in 0.2 s, "one blended skin"; voxel remesh 0.06 plus QuadriFlow 1,000 faces: 1,750 triangles in 1.1 s; Skin modifier on a 12-vertex stick skeleton plus Subdivision 2: 2,888 triangles — `docs/vault/06-art-pipelines/Character-Pipeline.md` section 2.3
- The prototype on four species: 1 to 3 s per build, 20 s per lit render, "a soft species with no thin parts is about 5 to 10 minutes, a limbed one with ears or a tail 15 to 25"; "QuadriFlow refused every polygonized skin ('the mesh needs to be manifold and have face normals that point in a consistent direction')"; thin parts, halos and rings must stay separate shells; "A metaball cannot make a sharp edge" — `docs/vault/06-art-pipelines/Sculpt-Pass.md`
- Blender manual (3.x-era mirror): "Meshes often need to be retopologized if the mesh is going to be deformed in some way"; "Remeshing only works on the original mesh data and ignores generated geometry from modifiers, shape keys, rigging, etc."; QuadriFlow modes Ratio / Edge Length / Faces, Preserve Sharp, Use Paint Symmetry, Seed; Voxel Remesh builds "a new manifold mesh" with Adaptivity, Fix Poles, Preserve Volume; both lose all data layers — [retopology.rst](https://raw.githubusercontent.com/dfelinto/blender-manual/main/manual/modeling/meshes/retopology.rst)

**Studio and Roblox constraints that shape the route**
- Importer formats: `.fbx`, `.gltf`, `.obj`; "The `.fbx` and `.gltf` formats support multiple mesh objects and hierachies, basic and PBR textures, cage mesh objects, rigs, avatar components, animation data, and vertex colors"; settings include Rig Type (R15, Custom, No Rig), Merge Meshes (off by default), Ignore Vertex Colors (off by default), Scale Unit, Insert Using Scene Position, Set Pivot to Scene Origin (on), Anchored — [studio/importer.md](https://github.com/Roblox/creator-docs/blob/main/content/en-us/studio/importer.md)
- Blender FBX export for Studio: Transform > Apply Scalings = FBX Unit Scale; Armature > disable Add Leaf Bones; disable Bake Animation "Unless exporting content with animation keyframes" — [export-requirements.md](https://github.com/Roblox/creator-docs/blob/main/content/en-us/art/modeling/export-requirements.md)
- Rig rules: bones frozen at scale 1, root at 0,0,0, "A vertex can not be influenced by more than 4 bones or joints", no influences on the Root — [specifications.md](https://github.com/Roblox/creator-docs/blob/main/content/en-us/art/modeling/specifications.md)
- Vertex painting is an endorsed Roblox route: "Many Roblox creators use vertex painting in conjunction with Studio's default materials, `MaterialVariant` objects, and `SurfaceAppearance` objects to create visual complexity on otherwise simple 3D objects" — [art/blender.md](https://github.com/Roblox/creator-docs/blob/main/content/en-us/art/blender.md)
- The grey-import problem is universal: vos_studiostt's GLBs arrived as "gray silhouettes" and he fixed it with ReplicatedStorage data modules; this repo fixes it with `materials.json` restored by the loader — `media/tiktok/NOTES.md` (ZPLSah2VR) and `docs/vault/06-art-pipelines/Map-Dressing.md`

### Inferences
- The recipe-to-metaball-to-decimate route is the only one that satisfies all five constraints at once (no artist, no GPU, no money, deterministic, versioned); the AI-generator route is a form explorer for a handful of hero species, not a roster pipeline, because every generated mesh still needs the same cleanup and a facing and scale fix.
- The Blender MCP's value for creatures is the `look` tool (the `angles` sheet and the `frames` strip), not `execute_blender_code`: the build itself is better as a checked-in script run by `bpy`, as this repo does; lihfolk's "far more tokens for a minimal difference" is the same lesson from the other side.
- Where tools break, in order of pain: (1) sculpt strokes (not scriptable anywhere), (2) generated meshes (scale, facing, density, mushy faces), (3) colour loss on GLB upload (fixed by data), (4) QuadriFlow's manifold requirement on polygonised skins (fixed by voxel remesh first, or by decimate), (5) animation (a separate tool chain, KQ5).

### Gaps
- No public, reproducible Claude-driven cute-creature pipeline was found on GitHub, YouTube, TikTok or X; the "Claude Blender Roblox References Setup" TikTok discover page exists but could not be opened.
- The note.com guide and the Glama fork listings could not be read, so the claimed tool counts for kleer001, blender-studio-pro-mcp and the 359-tool server are unverified.
- Whether Blender 4.1+'s Smooth by Angle modifier survives a GLB export as custom normals in Studio is still this repo's open probe (Sculpt-Pass: the FBX exporter was left on face smoothing).

## KQ2. Which generation service gives the best cartoon-cute result for the money, and does its licence allow a commercial Roblox game?

### Takeaway
No source read first-hand ranks the services on cartoon-cute output; every price and licence figure below is a search snippet or a third party, because all vendor domains were blocked. What is solid from source code: the Blender MCP's own Rodin call sends the cheapest settings (`tier: "Sketch"`, `mesh_mode: "Raw"`) and imports a GLB with no scaling or orientation; Tripo through the add-on is "only offered through Premium"; Tripo's v3 API (read through an MCP wrapper's docs) has a dedicated low-poly model (`P1-20260311`), a `retopologize` tool with `targetFaces` and `quad`, rigging and preset-animation retargeting, with observed costs of 40 credits for a P1 low-poly text-to-3D and 50 for the detailed H3.1 model. Commercial use on Tripo and Rodin paid tiers is consistently reported; the free tiers are disputed between sources, so the rule is: do not ship a free-tier model without reading the current terms.

### Inferences

## KQ4. How do people make the single-skin fluid look in Blender from Claude (sculpt through bpy, metaballs, remesh, subdivision, retopo with QuadriFlow or Instant Meshes) and which shading tricks (auto smooth, weighted normals, bevel shader) survive export?

### Takeaway
Sculpt strokes are off the table for any script or MCP, so the fluid look comes from volumes that fuse (metaballs, the Skin modifier plus Subdivision, or a boolean union followed by a voxel remesh and smoothing), then a reduction to budget (Decimate for a first pass, QuadriFlow for anything that will deform). Of the shading tricks, only geometry and normals survive export: a Bevel modifier and custom normals (Weighted Normal on a Smooth-by-Angle base) go into the GLB; the Bevel shader node is Cycles-only and render-time, so it never reaches Roblox.

### Cited Findings
- Sculpt via code: see KQ1 (operators need a context; blenderwright "Sculpt strokes cannot be simulated"; the animation skill refuses background Blender) — [info_gotchas_operators.rst](https://raw.githubusercontent.com/blender/blender/main/doc/python_api/rst/info_gotchas_operators.rst), [blenderwright](https://raw.githubusercontent.com/HoldMyBeer-gg/blenderwright/main/README.md)
- Metaballs, measured here: "A metaball element of stiffness s, reach r and threshold 0.6 has its surface at r * sqrt(1 - (0.6 / s)^(1/3))"; `object.convert` polygonises "0.1 s for 50,000"; Decimate with a vertex group keeps the face dense; "Its symmetry option leaves flipped slivers on the mirror plane"; custom normals set with `Mesh.normals_split_custom_set_from_vertices` "survives `object.join` and the glTF exporter writes it; the FBX exporter was left on face smoothing, so the FBX is flatter than the GLB" — `docs/vault/06-art-pipelines/Sculpt-Pass.md`
- Metaball versus remesh on real species: metaballs keep hooves, antler tines and blossoms; voxel remesh at 0.018 of the height erodes them ("a 0.1-stud antler is one voxel"); metaballs are "three to four times faster"; remesh "is the fallback for hard-surface bodies (crystals, planks)" — `docs/vault/06-art-pipelines/Sculpt-Pass.md`
- Thresholds that matter: "at threshold 0.12 to 0.15 and stiffness 2.0 parts blend; at 0.5 they stay separate balls"; the voxel plus QuadriFlow route "is smoother and slower"; "QuadriFlow is the one to use if we rig" — `docs/vault/06-art-pipelines/Character-Pipeline.md` section 2.3
- Blender manual on remesh and retopology (3.x mirror): voxel remesh makes "a new manifold mesh"; QuadriFlow "produce[s] a quad mesh with few poles", "slower but higher quality", Faces mode takes a target count, Preserve Sharp, Use Paint Symmetry, Seed; "Meshes often need to be retopologized if the mesh is going to be deformed" — [retopology.rst](https://raw.githubusercontent.com/dfelinto/blender-manual/main/manual/modeling/meshes/retopology.rst)
- Instant Meshes: only named in this repo's source list (`wjakob/instant-meshes`); no 2026 Claude-driven use found — `docs/vault/06-art-pipelines/Character-Pipeline.md` Sources
- Bevel shader node: labelled "Cycles Only"; "changes only the shading, not the geometry"; "a very expensive shader" that "may slow down renders by 20%"; recommended "mainly for baking or still-frame renders"; the Bevel modifier is the faster alternative but "sometimes fails on complex or messy geometry" — [bevel.rst](https://raw.githubusercontent.com/dfelinto/blender-manual/main/manual/render/shader_nodes/input/bevel.rst)
- Weighted Normal modifier: "changes the custom normals of a mesh"; modes Face Area, Corner Angle ("the method Blender uses by default"), Face Area and Angle; Keep Sharp; Face Influence (weak/medium/strong set by a Bevel modifier's Set Strength); in the 3.x manual "This modifier requires custom normals to be enabled" (the old Auto Smooth) — [weighted_normal.rst](https://raw.githubusercontent.com/dfelinto/blender-manual/main/manual/modeling/modifiers/modify/weighted_normal.rst)
- This repo's builders on `bpy` 5.0.1 already use "shade smooth by angle, a two-segment bevel on thick cubes and cylinders, a greyscale vertex gradient ... exported as `COLOR_0`" — `docs/vault/06-art-pipelines/Surface-Pass.md`
- glTF exporter (3.x manual): Y Up "Export using glTF convention, +Y up"; Normals "Export vertex normals with meshes"; Vertex Colors "Export Color Attributes with meshes"; Apply Modifiers exports "the evaluated mesh"; Draco compression available; "Include All Bone Influences: Allow more than 4 joint vertex influences. Models may appear incorrectly in many viewers"; animations from active actions and NLA tracks — [scene_gltf2.rst](https://raw.githubusercontent.com/dfelinto/blender-manual/main/manual/addons/import_export/scene_gltf2.rst)
- Roblox side: the Importer reads vertex colours from `.fbx` and `.gltf` (toggle "Ignore Vertex Colors"); vertex painting is an endorsed stylised-workflow technique; and a DevForum tutorial (snippet) says imported vertex colour is multiplied by the MeshPart `Color`, so set it to white **(snippet)** — [studio/importer.md](https://github.com/Roblox/creator-docs/blob/main/content/en-us/studio/importer.md), [art/blender.md](https://github.com/Roblox/creator-docs/blob/main/content/en-us/art/blender.md), [devforum 3050119](https://devforum.roblox.com/t/3050119)
- Roblox's own agent harness for assets uses the same reduction chain: `remesh`, `decimate`, `smooth`, `shade_smooth`, `recalc_normals`, `fill_holes`, `keep_largest`, then `uv_unwrap` and `bake_texture` to one 1024 px map — [3D-Asset-Agent](https://raw.githubusercontent.com/CodeByJN/3D-Asset-Agent/main/README.md)
- Roblox's own `GenerationService` says its newer meshes have "less pronounced baked‑in lighting", which confirms baked lighting is the usual artefact of generated textures — [parts/model-generation.md](https://github.com/Roblox/creator-docs/blob/main/content/en-us/parts/model-generation.md)

### Inferences
- The exportable "fluid" toolkit is: fused volume (metaball or skin modifier), voxel remesh only when hard edges or manifoldness are needed, QuadriFlow only if the mesh will be skinned, Decimate otherwise; a Bevel modifier for chunky hard parts; Smooth by Angle plus Weighted Normal written as custom normals into the GLB; colour as vertex colour or a small baked palette. Everything else (bevel node, Cycles AO, subsurface) is for review renders only.
- The 4.1+ change from Auto Smooth to the Smooth by Angle modifier is why older tutorials' "enable Auto Smooth then add Weighted Normal" no longer applies verbatim; the repo's builders already use the new call **(memory for the version boundary; first-hand that the call works on 5.0.1)**.

### Gaps
- The current (4.x/5.x) Blender manual could not be fetched; the QuadriFlow manifold requirement is documented here only by the repo's own error message, and the Smooth by Angle modifier page was not read.
- No source was found that confirms how Studio treats custom split normals from a GLB versus an FBX; the repo's probe is still open.

## KQ5. How do they animate (idle, walk, hatch) and bring animations into Roblox?

### Takeaway
Three routes exist in 2026, and none is "generate it in the viewer": (1) author in Blender on an armature and move it to Roblox with a Blender-to-Roblox animation add-on and its Studio plugin (the route the Claude R6/R15 animation skills use), (2) import a rigged FBX or glTF with keyframes through the 3D Importer (rig type Custom for a creature) and publish from the Animation Editor to get an asset id, or (3) buy rigging and preset animations from the generator (Tripo `rig_model` and `retarget_animation`, Meshy rigging). For a non-humanoid creature the engine needs an `AnimationController` with an `Animator`, bones become `Bone` objects, and a vertex may have at most four influences. Hatch and reveal beats in the references are done with VFX and camera in Studio, not with a skinned animation.

### Cited Findings
- Playing on a non-humanoid rig: "To play animations on rigs that do not contain a `Humanoid`, you must create an `AnimationController` with a child `Animator`" — [animation/using.md](https://github.com/Roblox/creator-docs/blob/main/content/en-us/animation/using.md)
- Rig representation and limits: Studio represents an imported rig with `Bone` objects; bones frozen at scale 1, root at origin, "A vertex can not be influenced by more than 4 bones or joints", "Do not apply influences to the Root bone"; rigging and skinning tutorials are Blender 3.0 based (armature, Parent With Automatic Weights, weight paint) — [rigging.md](https://github.com/Roblox/creator-docs/blob/main/content/en-us/art/modeling/rigging.md), [specifications.md](https://github.com/Roblox/creator-docs/blob/main/content/en-us/art/modeling/specifications.md), [rig-a-simple-mesh.md](https://github.com/Roblox/creator-docs/blob/main/content/en-us/art/modeling/rig-a-simple-mesh.md)

## KQ6. How does the result reach Roblox Studio (3D Importer versus Open Cloud, the Roblox Blender plugin, Studio MCP), and how does the Obsidian vault fit in?

### Takeaway
Four doors into Studio exist: the Importer (preview, error checks, rig and vertex-colour settings, SurfaceAppearance from PBR textures), the Open Cloud Assets API (headless, GLB/FBX up to 20 MB, a Model of MeshParts, moderation state in the Operation response, no preview), the official Roblox Blender plugin (MIT reference add-on that uploads selected objects as packages after a browser login), and the built-in Studio MCP (`insert_asset` by id, `generate_mesh`, `upload_image`, `screen_capture`, `execute_luau`). The vault is wired to Claude either by making the vault (or a repo folder) the working directory, or through an MCP server over Obsidian's Local REST API; the creators who show it keep a per-topic note that Claude reads before work and appends to after, which is what this repo already does with `docs/vault` and the daily log.
