## Key question 1: What exactly is Claude Design, who can use it today, and what does it output?

### Takeaway
Claude Design is an Anthropic product: launched 2026-04-17 by Anthropic Labs as a standalone site (claude.ai/design), moved into every Claude conversation on 2026-09-16, out of beta on 2026-10-08, included on every plan including Free, and reachable from Claude Code with `/design`. It produces editable artboards (HTML-based canvases: mockups, prototypes, one-pagers, posters) that export as PNG or PDF per artboard, or as .zip, PDF, PPTX and standalone HTML; it does not generate raster images, and no first-party page documents a 3D-object mode, star ratings, GLB export or Figma export. The standalone site, where the creators' "Model a 3D object" workflow lives, closes on 2026-12-14.

### Inferences
- Two different things are called "Claude Design" in the references: (a) the standalone Labs app (April 17 to December 14, 2026), which the creators used for 3D creatures and which has "Model a 3D object", star ratings and a GLB download on screen; (b) the in-chat Design artifact since September 16, 2026, which is an artboard canvas for 2D screens and posters with no documented 3D mode. The team's Tools-Status row and the creator videos refer to (a); anything we adopt now is (b).
- Because the standalone's projects are not migrated, its chats are deleted at closing and its public links will break, any creature pipeline built on the standalone 3D mode has a hard stop on 2026-12-14 with no documented successor. The migration article's "More details about moving your projects ... are coming soon" is the only hint that something follows.
- A Claude Design artboard is HTML/CSS/SVG code, not a bitmap. That is why "PNG export" exists only as a render of an artboard and why Claude cannot produce painterly concept art, textures or icons: raster look comes from uploaded images (our Blender renders) placed in the artboard, not from Claude.
- `/design-sync` is for React component libraries; our UI is Luau built from `src/shared/Theme.luau`, so the right route is a "## Design system" block in CLAUDE.md (which Claude Code artifacts read) or a Design System artifact made in chat from the theme values, not `/design-sync`.
- Claude Motion is the natural tool for an animation reference, but it is Team/Enterprise only; on Pro or Max the hatch-animation reference must be an interactive artboard or a plain HTML artifact, which the artifacts doc shows is supported (sliders for "easing curve, duration, and delay" with "the animation live").

## Key question 2: Which parts of a Roblox creature or UI can it produce to a shippable standard, and which only to a reference standard?

### Takeaway
Nothing from Claude Design ships into the Roblox build directly: our UI is Luau from a theme module with Scale-only sizing, our creatures are Blender meshes, and our icons are Blender renders. To a reference standard it is strong for UI screen mockups at phone size, species concept sheets (layout, silhouettes, palettes), thumbnail comps built from uploaded renders, and a timed hatch-animation prototype; to a shippable standard it produces only text-level artefacts (a reviewed spec, token values, timing numbers). Its 3D creatures, as the creators themselves show, are assembled-part viewer models whose GLB arrives in Studio grey and without animation.

### Inferences
- Shippable from Claude Design: none of the pixels. What ships is derived data: a reviewed screen layout the Luau builder reproduces with Scale values; token values (hexes, radii, gloss band height) copied into `Theme.luau`; animation beats and durations (ms, easing) copied into a data table under `src/shared/data`; a thumbnail composition plan handed to `store_compose.py`.
- Reference-standard and worth doing: (1) phone-size UI mockups for the screens Ethan is unhappy with, because the canvas renders real Fredoka (Google Fonts) with outlines, gloss bands and rarity colours in CSS, so a reviewer sees the intended look before code; (2) a species concept sheet per creature (name, three-word concept, hero feature, goofy thing, palette swatches with hexes, greyscale silhouette thumbnails, tier overlay notes) as artboards, using uploaded Blender renders for the model views; (3) three 1920x1080 thumbnail comps using uploaded `store_renders.py` output, with the "text out of the bottom band" rule drawn as a guide; (4) an interactive hatch-reveal artboard that plays the beats with sliders for timing.
- Not reference-worthy for us: 3D creature geometry (dark, part-assembled, off-style, grey on import, standalone-only, closing December 14) and icons or textures (Claude does not raster-paint; our bar is a rendered 3D icon from Blender).
- Vector silhouettes drawn in SVG could be useful for the greyscale thumbnail legibility test the design doc requires, since the test is about shape, not shading.

## Key question 3: What is the "handoff document" pattern creators use, and what goes in it?

### Takeaway
In the creator's footage the "handoff document" is a long context script the standalone app writes so a fresh chat can continue with every earlier decision ("starts a new conversation with an entire script for everything that you've done"); the creator then opens a new chat, pastes the species request "with the previous details mentioned in mind", adds a reference image, and iterates with a second prompt that lists changes and names which part of the reference to copy, rating each result. Anthropic's own "handoff" means something else (Export > Send to Claude Code or another app), and no first-party page describes a handoff document; our repo already runs the same pattern with `Handoff.md`, the Board and the daily log, and the `design-handoff` skill in this session gives a ready spec skeleton.

## Key question 4: How does a Claude Design creature reach Blender or Roblox, and is the animation exported?

### Takeaway
The observed path is: download the GLB from the standalone 3D viewer, rename the file to the exact species name, File > Import in Studio, and accept a grey, untextured, unanimated model; colours and effects are then rebuilt by Claude-written ReplicatedStorage modules (vos_studiostt) or a Lua "installer" pasted into the command bar (lihfolk). Animation is not in the GLB: both creators animate afterwards in chat, and the repo's note says plainly "the viewer's animation absent from the exported GLB". No first-party page documents GLB export or its contents, and no reference shows a Blender import of a Claude Design GLB.

### Inferences
