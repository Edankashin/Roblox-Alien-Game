# UI Playbook

The look, written to the level Claude can build from. Hex values here are the starting palette; the team's choices in PRE_PRODUCTION section 2 replace them. When a review corrects a panel, update this file in the same change.

> **The UI is moving to block cells ([[Decisions]] B44 and B46, [[Decide-Now]] 43 a), one screen per change, HUD first.** The rules are [[#Block cells (2026-10-21)]]. A screen built in block cells follows that section where it differs from the older lines below (rounded corners, gradients, the gloss band, pills); a screen not yet rebuilt keeps the older lines until its own change. The HUD is in block cells as of 2026-10-21, and every other screen under `src/client/UI` since the same day ([[#Screens after the HUD (2026-10-21)]]), the capture bar and the Reveal last ([[#The reveal in block cells (2026-10-21)]]): one look across the whole game.

## Font and text
- Fredoka One for all UI text; Builder Sans only for long settings text.
- Sizes: 14 minimum on mobile, 18 body, 24 labels, 36 titles, 48 reveal text.
- Any text over the world gets a UIStroke of 2 to 3 px, colour `#1B1F3B`.
- **Stroke join.** Every stroke sets `LineJoinMode`, never the default Round: Bevel on a text outline (`Theme.Stroke.TextJoin`), Miter on a border round a frame, button or input (`Theme.Stroke.ShapeJoin`). `Builder.stroke` picks by what the stroke wraps (a Contextual stroke on a TextLabel or TextButton is text; the border modes are shapes), so a screen never sets it. Source: the X pass ([[X-Posts]], take 1). Not yet looked at in Studio: check the counters of e, a, g and the sharp joins of k, v, w in Fredoka One at Reveal size (48); if Bevel looks wrong there, flip the one line in `Theme.Stroke`.
- **Stroke thickness follows the screen height.** `UIStroke.Thickness` is pixels and takes no Scale, so a fixed 2.5 px is thin on a big window and heavy on a phone. `Theme.Stroke.Text` 2.5, `Button` 3 and `Panel` 4 are the pixels at a 1080 px tall screen (`ReferenceHeight`); `Builder.stroke` multiplies by the screen height over 1080, held between 0.8 and 1.2 (`Shared/StrokeMath`, `MinScale` and `MaxScale`). So text is 2.0 px under 864 px tall (every phone, a 768 px tablet), 2.5 at 1080 and 3.0 from 1296 px tall up (1440p, 4K), which is the 2 to 3 px rule above, a button border 2.4 to 3.6, a panel 3.2 to 4.8. The height is the camera's `ViewportSize`; one listener in Builder sets every stroke again when it changes (a rotation, a resize, the device emulator). Rules for a screen: never write `stroke.Thickness`; change a stroke with `Builder.setStrokePx(stroke, Theme.Stroke.Panel)`, tween to `Builder.strokeThickness(px)`, and ask which stroke it is with `Builder.strokePx(stroke) == Theme.Stroke.Button` (the scaled `Thickness` no longer equals the Theme number). The loading screen (ReplicatedFirst, cannot require Shared) mirrors the reference, the clamp and the text join, and scales its two text outlines the same way ([[#The loading screen in block cells (2026-10-21)]]).

## Buttons

## Panels
- Solid cream body, thick coloured border, UICorner 16 px.
- Header tab with the title in white outlined text.
- Close: red, square-ish, white X with black stroke, about 80% of the header height, top right, same place on every panel.

## Icons (batch 4)
- On a block-cell screen the 8 by 8 pixel icons of `src/shared/data/PixelIcons.luau` come first (`Builder.blockIcon`; see [[#Block cells (2026-10-21)]]); the flat pack below is the fallback for a key with no pixel icon, and stays the icon on the rounded screens.
- The set: 128 px flat two-tone icons with a thick dark outline (about 6% of the width), modelled in Blender and rendered into `assets/icons` (the three weather particle sprites into `assets/particles`). One style for the whole game; never mix packs, and a thin outline next to a thick one reads as broken.
- Ids: each file name is its key in `src/shared/data/Icons.luau` (`Icons[key] = assetId`, 0 meaning not uploaded yet). `Aliases` map a data id whose icon has another key (Gear "Boots" uses `SpeedBoots`). `Particles` holds the weather sprites (Raindrop, Flake, Wisp).
- Use: `Builder.icon({ key = ..., parent = ..., position/size/anchor in Scale })` returns an ImageLabel (transparent background, `ScaleType` Fit), or nil with nothing created while the id is 0 or the key is unknown. `Builder.button` takes `icon = key`: once the id is uploaded the face shows the icon centred at 0.7 of its size (`BUTTON_ICON_SCALE`) and no text, and the icon presses with the face.
- Fallback: with an id of 0 every spot shows what it showed before the pack: the `MENU_GLYPH_<id>` letter on a button face, the gold square on the Scrap pill, the purple square on the event banner, Roblox's default particle in the weather. The game must always run with any id at 0, so never build a layout that needs the image.
- Where they show: the left menu stack (Shop, Aliens, Codex, Ship, Quests, Gifts) and the round top buttons (Settings, Ranks), both keyed by the menu id; the Scrap pill's square (`Scrap`); the event banner's square (`Hud.SetEventBanner`'s fourth argument, e.g. `Shower`; the server luck banner has none yet); the weather sprites (`texture` in `data/Weather.luau`, read by `WeatherFx`). Where an icon fills a backing square, the square and its outline go transparent while the image shows, since the icon carries its own outline.

## Shop
- **Superseded 2026-10-15 by [[#Shop shelf (2026-10-15)]]**: the Shop is a full-screen shelf of tall cards now, and the tile bands below describe the old panel. They stay as history; what carries over is the about-line rule (every Robux price shows "about $N.NN" under it, one 14 px line, hidden with the price), the fit-pass method (measure before writing a string) and the tap-sinking lesson (the shelf's card is one tap target under inert labels).
- Shop layout (old panel): large tiles for bundles and the biggest purchases, small tiles for singles.
- Every Robux price carries an "about $N.NN" line (GAME_DESIGN 14; `ShopMath.AboutLine` over `Shop.RealCurrency` and `SHOP_ABOUT_PRICE`). It sits directly under the price button, centred, on the Starter Pack tile and every small tile: one 14 px line (`TextScaled` off) in the Common grey with the usual navy outline, in a band 17 px high at 667x375, one line ("about $12.48", the longest, is 84 px in Fredoka One, 98 px at the widest recorded 8.1 px per glyph, against a 123 px box). It is an estimate, hence "about": Roblox sets the real regional price when its purchase prompt opens. It shows exactly when the price button shows (the Owned and Claimed chips hide both; "Pick your Rare first" keeps it). It went under the button, not into a thin band above it, and the tiles grew to fit (small tiles 1.4 to 1.15 wide over tall, then 1.15 to 1.05 when the description needed its second line, the Starter Pack tile 0.85 to 0.93 of the page); on a spin tile it clears the gold "Tap for the odds" line and the tap band, which end above the button.
- Small tile bands at 667x375 (the page is 282.3 px wide, the tile 136.9 x 130.4 px at aspect 1.05, fractions of the tile in `ShopScreen`'s `TILE_*`): name 3.5 px down and 37 px high (two 14 px lines, a line is 17 px), description 40.7 px down and 36.5 px high (two 14 px lines, `TextScaled` off at the 14 px floor, `TextTruncate.AtEnd` as the last resort), price button 78.2 px down and 32 px high (0.11 of the panel, over the 26 px tap floor), about-line 110.8 px down and 17 px high, 2.6 px of card under it. At 1.15 the description band was 17.8 px, one line, and every pass and boost description (`TextFits` false in the 2026-10-14 Studio run at 1081x436) ended after four words. A gold shared-boost note ("Everyone, 15 min", 112 px against 123 px) and the Spins tiles' gold "Tap for the odds" take the description band as one centred 14 px line; the odds tap band runs from the description's top to the button's top (37.6 px). Two 123 px lines hold roughly 210 px of text: the Spins strings (187 to 214 px) fit whole, the pass and boost strings (276 to 566 px, three to six lines) end in an ellipsis until they are shortened to about 26 characters; a smaller size is not the fix. The Starter Pack's description is three lines (51 px of a 55 px band at 667x375, 634 px of text in a 260 px line) and is not touched by the small-tile aspect.
- **Everything on a Shop tile sinks taps.** `Builder.frame` and `Builder.label` leave `Active` false, and a tap on an inactive frame or label passes to the next thing under it: the full-screen Dim button that closes the screen (a tap on an about-line closed the Shop once in the 2026-10-14 run). So the panel, every tile card and every plain label on a tile (name, description, odds line, about-line, "Your Rare") set `Active = true`; the Spins tile's `OddsTap` and the Buy button are their own targets a ZIndex above the labels. Any new panel over a Dim does the same: `Active` on the panel, or the first tap that misses a button dismisses it.

## Toasts and reveals

> Toasts and banners are in block cells since 2026-10-21 ([[#Screens after the HUD (2026-10-21)]], "A transient is edged"); where the lines below say pill, read edged block.
- Toasts top centre, slide down with a small bounce, icon left, gone in 2.5 s, at most three stacked. A line that does not fit one line at the 14 px floor makes its pill taller (two or three lines, measured with `TextService`), never cut.
- An action toast (`Toast.ShowAction`, 2026-10-22) is the one toast a player can tap: one chunky block button on its right end, 0.3 of the toast wide and 0.72 tall, a flat face in the colour of where it leads, outlined white text at the 14 px floor, the 44 px hit area, the click on every tap; the line's text stops 0.02 short of it (and wraps there). A tap runs the action and takes the toast down. It stays `seconds` (the caller's data, longer than 2.5 s so there is time to tap) and queues, hushes and replays like any toast. Its one use: the "Earn faster" chip on "Need N more Scrap" ([[Decisions]] B51), Boosts blue, opening the Shop at Scrap Magnet. Never a purchase prompt from a toast.
- Reveal: backdrop dims 60%, then the three beats of [[#The reveal in three beats (2026-10-15)]]: an egg to tap and crack, shards and rays in the tier colour with the tier word and confetti for Epic and above, and the card that drops in with the chance line, the chips and the two buttons, "Tap anywhere to continue". (Until 2026-10-15 it was one beat: the card scaled in with a Back ease over a radial burst.)
- A Reveal that follows a server grant (an egg claim, a Peddler egg) starts its quiet moment at the tap, not at the answer: `Toast.QuietFor(Config.GrantRevealQuietSeconds)` just before the InvokeServer, because the server's announcement and the quest toasts land before the card can open. In `Reveal.Show` the order is `open = true`, then `Toast.Hush()`, then `build()`: Hush starts the queue's drain, which draws at once unless the quiet probe already reads true, so Hush before `open` replays the hushed toasts over the card.
- The phone rules from the research (the reveal's three beats, the event chip, insets, hit areas, text size, thumb zone) are in [[#Phone rules from the design research (2026-10-15)]]; where they differ from the lines above they win once a screen is rebuilt.

## Event banner and compass (reference: `refs/dino-event-banner.jpg`)
- Since the block-cell HUD (2026-10-21) the banner is a Codex-purple block plate, the board's event chip, with the event's pixel icon (or a flat gold block) on the left and the luck chip a flat green block; its slot, its two lines and its rules below are unchanged. The compass strip is in block cells too (2026-10-21, [[#Screens after the HUD (2026-10-21)]]): a fitted flat block, the heading a flat block, the diamonds stepped pixel diamonds; the lines below that say pill, stroke, gradient and turned square are the old look.
- Event banner: top centre under the compass strip, a dark navy pill with the outline colour, aspect about 5:1. Event icon in a rounded square on the left, event name in bold white outlined text with the time left ("3:39 left") in smaller text beneath it, and a green (`#51DF51`) pill chip on the right reading "1.5x LUCK" whenever the event changes luck. Same slot for the Meteor Shower countdown and weather events; never more than one banner.
- Compass strip (`src/client/UI/Compass.luau`, numbers in `src/shared/data/Compass.luau`): its own ScreenGui at the HUD's layer (10). A thin navy (`Trough`) pill with the outline stroke and the usual gradient, top centre: 34% of the screen width (`StripWidth` in `data/Compass`, which the Hud reads to keep the round top buttons right of it; it was 38% and touched them at 4:3), 4% of its height (about 15 px on a phone in landscape, so the 14 px minimum text fits), its top at 0.006 (so it ends at 0.046). The cardinal letters N, E, S, W (white outlined, minimum text size) and tick marks every 15 degrees (short white frames, taller every 45) slide along it as the camera turns; north is world -Z, east +X, clockwise, the same as the Radar's player marker, taken from the camera's look yaw. A thing `delta` degrees from the heading sits at `0.5 + delta / 180` across the band and is hidden beyond 90 degrees either side; within 15% of either end it fades up to 60% transparent. A small dark pill at the centre (the Trough darkened, outline stroke) reads the heading in whole degrees ("270°", 0 to 359); it covers the letters and ticks behind it, but diamonds draw over it so a marker dead ahead is never hidden. Refreshed 20 times a second, and only while shown (it hides with the tutorial hint: capture, reveal, an open panel or the opening cinematic).
- Compass diamonds: a square turned 45 degrees with the outline stroke, 55% of the band's height, one per data marker, coloured by kind: the waypoint (tutorial or Field Notes marker, or an alien marked from the radar by name) and the Peddler gold (`Featured`), the radar target blue (`Select`), the camp green (`Confirm`), the shrine orange (`Legendary`), the cave mouths purple (`Codex`), the Great Vent red (`Close`). A marker shows only while the player is at least its minimum distance away (so it is not in your face), and the lowest priority number draws on top where two overlap (the waypoint over the radar target on the same alien).
- Compass line: under the band, one line in white outlined minimum-size text, "Camp 42m": the name and the flat distance in studs, floored. It names the marker on the strip with the lowest priority number (waypoint, then target, Peddler, camp, shrine, caves, vent), the nearest of equals, using the waypoint's own label when that is the marker. It keeps its marker half a second before switching, so two at similar distance do not flicker, and switches at once when its marker leaves the strip; with nothing on the strip the line is hidden.
- Centre column under the strip: the ship bar, the luck line or event banner and the Friend Boost chip sit 0.046 of the screen height lower than before (ship bar top 0.071, banner top 0.151, Friend Boost chip top 0.226; `CENTER_SHIFT` in `Hud.luau`), the strip's height plus a gap. The Scrap pill, the clock chip, the round top buttons, the biome and shower chips and the menu stack did not move. Toasts start at 0.29 in both states, under the whole centre column (the Friend Boost chip is always shown and ends at 0.281); a toast higher than that covered the chip. A radar-marked alien is one diamond, not two: the target marker yields to the waypoint when both point at the same spot.
- Verb markers: floating "✦ Collect" labels over nodes, white outlined text with a small glyph, visible from far away; the noun appears within nameplate distance.

## Radar minimap (Radar Mk1 and up; `src/client/UI/Radar.luau`)
- Where: right edge under the Meteor Shower chip, in the slot the free Nearby column otherwise starts in (right edge 0.985, top 0.225). A square holder 14% of the screen width, kept square by an aspect constraint, so its height follows the viewport. The free Nearby column hides while a radar is held (the blips carry the same caught/uncaught reading, placed; the column's remaining 0.14 of height would not fit its rows) and comes back if the tier ever reads 0. Hidden with the other HUD extras during a capture, a reveal or an open panel, and absent altogether until the server says a radar tier is held.
- Disc: a navy (`#1B1F3B`) circle with the 3 px outline stroke and the usual vertical gradient. The cardinal "N" sits at the top in white outlined Fredoka One (label size). The map is north-up and never rotates: world -Z is up, +X is right, and the tier's range is the disc radius.
- Range ring: a faint blue (`#68C9FE`, 60% transparent, text-stroke thickness) circle at half the radius with a small "60m" label on its top edge (half the range), so distances read at a glance.
- Player: a gold (`#FFC83D`) diamond at the centre with a small white dot on its tip; the whole marker turns to the camera's look yaw, so the dot shows which way the player faces while the map stays put.
- Alien blips: one round dot per wild alien within range, 10% of the disc, with an invisible tap area twice that. Caught species: filled in the tier colour with the navy outline. Uncaught species: the silhouette rule, a dark fill with the ring in the tier colour. A Secret-tier alien is never a blip (see Radar Mk2 below): Mk1 draws nothing for it. An alien the server reserved for this player (a trainee, the summoned Warden) gets a gold ring; one reserved for someone else is not drawn at all. Blips at the edge of the range are kept fully inside the disc.
- Camp and Peddler: a small cream (`#FFF4DC`) square for the ship and a gold diamond for the Peddler while it visits, both pinned to the rim when out of range so they point the way. Nothing else on Mk1; nodes and hidden spots come with Mk2.
- Tap to mark: tapping a blip clicks and hands the alien to the bootstrap, which sets the world waypoint on it ("Marked: Moop") and clears it on arrival. The client only draws: which radar is held, which aliens stand where and who may see them are the server's.
- Radar Mk2 (`Radar.Mk2` in `data/Radar`, held when `gear.radar >= Mk2.Tier`): a Secret-tier alien in range is a "???" ping, not a blip: a dark disc 32% of the radar disc with a white ring (gold if reserved for you) and white outlined "???" at the minimum size, tappable like a blip. Mk1 draws nothing for a secret. While a ping is on the disc a heartbeat plays and every ping swells to `SecretPulseScale` and back within the beat, every `SecretPingFarSeconds` at the full range down to `SecretPingNearSeconds` at `SecretNearStuds` or closer (linear in the nearest secret's distance); no secret in range, no sound. From Mk2 the Nearby column comes back under the disc (its top follows the disc's bottom edge, its bottom stays put) as a compact "not now" list, shown only while the disc shows: for this biome's species of tier `AbsentMinTier` and up listed under a condition not active now (uncaught first, then higher tier), up to `AbsentRows`, each row two lines of minimum-size text with no icon, left-aligned and outlined, the name and under it the condition in the Select blue ("in the rain"). A row needs two 14 px lines (1.25 line height) in pixels, so the list shows as many as fit, one at iPhone SE size and three on an iPad, and with nothing absent or no room the whole column hides. (Where the column sits at its default top at Mk2 it lists the species that are out, then dimmed rows with a small icon, but the bootstrap does not show it there.) The Shop's Gear tab gets a Radar Mk2 row after Mk1 (grey, "Unlocks with World 2", until a second world is unlocked and Mk1 held); five rows no longer fit, so that tab scrolls with the thin dark bar like the Robux page.

## Featured banner
- Full width, aspect about 2.6:1, illustrated background themed to the item, darkened, timer and odds visible.

## What to avoid
- Default grey Roblox buttons, Source Sans, Inter or Montserrat (or any web font: Fredoka One is the one face), glass or blur panels (no glassmorphism), outline-free card grids, emoji icons, gradient text, silence on tap.
- On a block-cell screen: a rounded corner, a gradient, a gloss band or a rendered round icon next to the blocks (two games on one screen, B44).

## Layers and banners (2026-10-05)

Display orders: HUD 10, tutorial hint 15, modal panels 20, the notifications ask card 45, toasts and server-wide banners 40, the launch fade 50. Toasts stay above panels because refusals from inside a panel must show. A wide banner (rare catch, Peddler landing) would cover a panel's header, so while any panel is open a banner slides up from the bottom edge instead of the top stack; with no panel open it stacks at the top as before. The toast stack itself starts lower while a panel is open.

## Input fields and hints (2026-10-05)

A text box is navy Fredoka on the cream panel colour with the outline border stroke only, no text stroke, placeholder in the Common grey. A hint line under a panel's rows is Fredoka too, navy, no stroke: the outlined white style is for titles and anything drawn over the world, never for fields or helper text.

## Grids inside scrolling frames (2026-10-05)

A UIGridLayout cell with a Scale height inside a ScrollingFrame resolves against the canvas, and the canvas grows to hold the grid's content, so the two feed back until the canvas is three pages tall and one card sits 150 px down. Inside a ScrollingFrame the cell height is therefore derived in pixels from the frame's width on every resize (the one place a pixel value is set), width and padding stay Scale, and the canvas is set to the page count from the row count. The Scale-only rule still holds for positions and sizes everywhere else.

## Capture bar variants (2026-10-05)

A variant (data/CatchVariants) changes how the one timing bar behaves, never how it is built. Since 2026-10-21 the bar is in block cells ([[#Screens after the HUD (2026-10-21)]], "The capture bar"): where the lines below say pill, read the edged block; the zones keep their exact edges. The drifting zone moves its centre along the bar with the shared sine from the server's phase while its widths stay put, and it freezes where the tap was scored while the verdict shows, so the player sees exactly what they hit.
The reel is hold and release: pressing starts the hold, the hint swaps to the held line ("Reeling... let go!") and the ticker pops; letting go is the tap.
The chase adds a countdown chip above the bar's right end, mirroring the lure chip on the left: Trough pill, white outlined text, turning red and popping once a second for the last three seconds.
Zone and ticker colours come from the variant row's Theme keys (Select and Featured for the reel, Confirm and Featured for the chase), so no new colours were added; the Standard bar looks as it always did.

## Alien card chips (2026-10-06)

A chip on the alien card is 0.38 of the card wide, with its text at 0.9 of that: the minimum text size is 14 px and an iPhone SE card is about 115 px, so anything narrower clips a five-letter word ("Elder" became "Elde" at 0.26). The chips sit in a row on the shape square's lower edge (shape at y 0.38, 0.36 wide; chips at y 0.59), below the shape's label, so neither covers it. A chip never holds more than five characters: the growth countdown shows whole hours or whole minutes ("2h", "59m"), never both.
Every text row on a square card is one line at the minimum size: a 0.17-tall slot is about 22 px, which holds one 14 px line, not two, so "gathering at the Picnic Table" clipped to its first line. The status is therefore the station's name alone ("Picnic Table"), and the countdown lives in the chip, never a third row.
A panel that opens by itself is its own message: a toast before it covered the header and a banner after it covered the bottom row, so the gift pop opens the Gifts screen with nothing over it.

## Overlay badges fit their longest name (2026-10-14)

The Studio retest found "Launch Gold" cut to "Launch" on the Reveal and "Launc" on an Aliens card: the badges were sized once for a short name, and a TextScaled label never goes under the 14 px floor, so a label narrower than its text wraps and cuts. A badge is now sized from the names. `Builder.overlayName` measures each `OVERLAY_<id>` string once with `TextService:GetTextSize` at the 14 px floor (Fredoka One: Launch Gold 84.0 px, Rainbow 56.5, Spectral 56.6, Crystal 49.9, Shiny 36.7, from `assets/fonts/FredokaOne.ttf`), and `Shared/BadgeFit` (pure, `tests/BadgeFit.spec.luau`) turns the px into a Scale of the parent: `(text px + 2) / (0.9 x parent px)`, with the badge's text at 0.9 of its width as for the card chips. Never narrower than the old width.

- Reveal: one line, the longest name sets it for every overlay (so the badge never changes size between catches), and the badge is right-anchored so it grows to the left, about 0.57 of the card at iPhone SE (168 px wide) and 0.5 at 192 px, toward the NEW! ribbon and no further than 0.92. The card's px come from the camera's viewport (the card is 0.6 x 0.56 of it at 0.8 aspect), not from the card's AbsoluteSize, which follows the open and pop tweens.
- Aliens card: the card is about 82 px at iPhone SE (667x375: a 395 px panel, a 379 px grid, 0.22 of it less the 6 px scrollbar; the "115 px" above is from an older layout) and the speed chip takes 0.40 of the top row, so a badge fits beside it only up to 0.55. Each card measures its own overlay name (a "Shiny" card keeps its small badge). A name wider than 0.55 takes the whole top row (0.92) and the speed chip and the Lv chip move to the row under it; a name wider than the row ("Launch Gold" under about 105 px, so every phone) wraps to one pill per word, "Launch" over "Gold", and the speed chip takes the row beside the short last word, the Lv chip the row under the pills. One pill per word rather than one tall two-line pill because a tall pill would push the speed chip into the size and growth chip row (y 0.52 to 0.66), and because each one-line label is measured exactly instead of leaning on how TextScaled wraps. The grid's resize hook (`layoutGrid`) refits every badge, so a window resize or a rebuild never leaves a stale size.
- A name that cannot fit even the whole row (a single word wider than about 0.92 of the card) still overflows; give it a shorter key (see "Short keys for dense places" below) before adding such an overlay.

## Visual quality bar (2026-10-06)

Superseded on block-cell screens by [[#Block cells (2026-10-21)]]: a block has no gloss band, no gradient and no bevelled 9-slice; its lit top row, shaded edges, grout and jitter are the finish. The rest of this section still holds for the screens not yet rebuilt.

The target look is the top Roblox sims (Pet Simulator 99, Adopt Me):
- Rendered glossy icons, each with an outline and a soft shadow, never flat glyphs.
- Bevelled 9-slice plates for panels, buttons and pills (to come, with the art pass).
- A gloss band on every button and chip: a white highlight across the top half of the face that fades out downward.
- An inner shadow at the bottom of every panel, so the plate reads as having thickness.
- A shine sweep on the one featured button per screen, never on two at once.
- Saturated two-tone colours (the lighter top of the gradient over the base colour), outlined Fredoka text, no blur and no glass.

What this change added, in code only (`src/shared/Theme.luau` `Theme.Gloss` holds every number, `src/client/UI/Builder.luau` the helpers):
- `Builder.gloss(target, corner?)` adds the "Gloss" highlight band (top `Theme.Gloss.Top` of the target, corners matching the target's). It is non-interactive and a child of the target, so it presses and scales with it. `Builder.button` calls it on every face automatically; `Builder.frame` and `Builder.pill` do it only when `gloss = true` is passed, because they are also plain containers. Children of a glossed frame need a ZIndex of the frame's plus 2 or more, or the highlight washes over them (a button's icon already is).
- `Builder.innerShadow(target)` adds the "InnerShadow" band across the bottom `Theme.Gloss.Shadow` of the target. Nothing uses it yet: each panel adopts it in its own change.
- `Builder.shine(target)` sweeps a diagonal white band across the target every few seconds inside a "ShineClip" frame, and returns a function that stops it. It does nothing under Reduced Motion. Nothing uses it yet: give it to the Face of the featured button when a screen adopts it.
- The gradient carries the transparency of all three bands (their frames stay opaque white or black underneath), because a UIGradient combines with the frame's own transparency and setting both would count it twice. Tune the look in `Theme.Gloss`, not in the helpers.

Still waiting on assets: the rendered icon pack (the Icons table keeps text glyphs until ids are uploaded), the 9-slice plate images that replace the flat rounded rectangles, and the bevel and rim-light baked into them. The gloss and inner shadow stay as code overlays on top of the plates; the shine stays code.

The card is the usual cream panel (`Theme.Colors.Panel`, UICorner 16, 4 px navy stroke), 0.5 of the screen wide in a box 0.7 tall at aspect 1.4 (about 333 x 238 px at iPhone SE size), with no header tab and no close button: the button is the way out. Top to bottom, all centred at 0.88 of the card wide:

- Time (`AFK_TIME`, "Resting for 0:12"): navy, no stroke, label size, m:ss and h:mm:ss past an hour. It counts up locally every second from the server's `since` against `workspace:GetServerTimeNow()`, so it is right without a push each second.
- Earned (`AFK_EARNED`, "Earned while resting: N Scrap"): navy, no stroke, body size, from the latest push (the server sends one every `Afk.CheckSeconds`). A nine-digit figure is the widest it gets: check it at the SE card width before lengthening the string.

When it hides and comes back: any local input (`InputBegan` of any type: a key, a click, a touch, a button) hides it at once (no shrink tween, which would race a quick re-show). The server wakes a player who moves (3 studs flat between two checks) or uses the game (any remote call), and then pushes `resting = false`: the screen is already gone, the toast "Welcome back! Your crew earned N Scrap while you rested" shows in the Confirm green, and the HUD rate returns. The "Back to play" button also tells the server (`AfkWake`), so it wakes the player at once even when they stand still. A screen hidden by input while the server still says resting (a key press or menu read that sent nothing to the server) shows again after `Afk.IdleAfterSeconds` with no input; a mouse or finger moving counts as input for that clock but does not hide the screen. A fresh rest always shows the card, even right after a key press (the server's word wins, which is also how `/afk` shows it in Studio).

The rejoin line: Roblox disconnects a player with no input for 20 minutes, so at `Afk.RejoinAfterIdleSeconds` (17 minutes) of `Player.Idled` or of the local input clock, whichever is larger, the client calls `AfkRejoin` once per idle stretch. When the server accepts (`AfkRejoining` event and the call's answer), the green button is replaced by a navy `Trough` pill with white outlined text, "Keeping your spot..." (`AFK_REJOINING`), 0.8 of the card wide in the button's place (the string is longer than the button). A hidden card comes back up to show it. In Studio the server only prints `Afk: would rejoin <name> to this server`; in a reserved or private server (homes, visits) it refuses and nothing shows, because the cutoff applies there and offline income covers it.

## UI fit pass (2026-10-07)

Fixes from the Studio run at iPhone 7 (667x375), iPad (1080x810) and narrow multi-client windows. The rules they leave:

- **Measure before you write a string.** At 667x375 a panel is about 395 to 526 px wide, so a label's box is (its Scale size) x (the panel's pixels), and the 14 px floor is a hard stop: text that is longer than the box wraps, a wrapped line needs another 17 px of height, and a label shorter than its lines cuts them. Measure the string in Fredoka at 14 px (Fredoka One advance widths are what Studio draws; "Scann" is 40.7 px, which is why the wheel's 41 px label stopped there) and leave 5 px of margin. A bad fit is fixed with a shorter key, not a smaller size.
- **Short keys for dense places.** The wheel's ring shows `SEGMENT_SHORT_<id>` (one word of at most 37 px, and two neighbours under 67 px together because the ring's labels are 34 px apart at the bottom: "Scan", "Pal", "Fast"), the Welcome Week tiles `GIFT_TILE_<label>` (one word of at most 46 px), and the odds table, the toast and the Tomorrow line keep the full name. A full name stays the truth; the short key is only for the crowded spot.
- **Two lines or none.** A band that may hold a long name is two 14 px lines high (34 px at the reference size): the Shop's small tiles are 1.05 wide over tall for that (1.4 before the about-line band was added, 1.15 before the description got its second line), so "+1 Slot on Every Station" wraps whole and a description has two lines. A band that must stay one line says so (`TextTruncate`) and its string is measured against it. A description band that holds a paragraph is sized for its line count (the Starter Pack's is three lines, 0.25 of the tile).
- **A note never gets its own thin band above a button.** The Server Luck tiles' gold line ("Everyone, 15 min") takes the description band, like the spin tiles' "Tap for the odds"; a 10 px band under the description wrapped to two lines and ran under the Buy button. The minutes come from the grant row, not the string.
- **Stack the lines that do not fit side by side.** The wheel's "Free spins" and "Banked spins" sit one under the other at the column's full width, 0.06 of the panel high each; two 84 px halves cut "Banked spins: 12".
- **The HUD's top row stops at the centre column.** The round top buttons stack leftwards from the clock chip until the next one would reach the ship bar (the clock chip's size, centred) or the compass strip (`Compass.StripWidth`); the rest stand in a column under the first, at the same x, where the biome chip and the radar are further right and the event banner further left. At 4:3 that is Settings in the row and Ranks and Playtime under it; at 19.5:9 all three fit in the row. The first button is always in the row.
- **Keep clear of the menu column.** The HUD's icon column (`Theme.Menu`, `Builder.menuRight(screenSize)`) is above every panel, and in a tall narrow window it is 0.12 of the width wide. A tray anchored at the bottom right keeps its right edge and gives up width (the Build tray); a centred panel slides right by what the column covers (the Ship screen). Wide screens leave both as they were.
- **Toasts wrap.** `Toast` measures the line with `TextService:GetTextSize` at the 14 px floor in the 0.81 text box and, over one line, makes the pill `lines * lineHeight / 0.7` tall (three lines at most); the stack uses that height. The measure is wrapped in `pcall` and falls back to the one-line pill.
- **Crowds of name plates thin out.** The aliens on display in a habitat test their plates nearest first every 0.2 s: a plate whose screen rectangle (`Habitats.PlateTextShare` of the billboard's width) would overlap a nearer plate's is hidden, and one already showing counts 1.5 studs nearer so two aliens trading places do not flicker. Never solve a plate overlap by lowering the plate into the alien.
- **A list of repeated names is counted.** The Visitor Book groups by name in the order of the latest visit ("Player2 x2"); the record keeps one entry per visit for the server.

## Phone rules from the design research (2026-10-15)

Ethan called the launch off over the UI bar ([[Decisions]] B27). The research ([report](../../../reports/Roblox%20creature%20UI%20and%20Claude%20workflows.md), section "Pro UI is a token system plus two painted asset classes") scored this Playbook: right on Scale-only, Fredoka One, outlined text, the red X, rarity colours with shapes, bundle tiles and the worded odds line; missing the rules below. They are drawn on the [Catch an Alien UI canvas](https://claude.ai/artifact/GsddVfW4nSoBSRpEpCSvi4) (HUD at 844x390 and 1080x810, Aliens, Shop, the reveal in three beats, tokens); how the canvas is used is in [[Claude-Design-Brief]]. The rules apply to every screen as it is rebuilt from the board Ethan picks; no shipped screen changes before then.

- **Insets.** Every ScreenGui with something to tap has `ScreenInsets = CoreUISafeInsets` (the engine default and the docs' recommendation for interactive UI; `None` behind a notch can hide a button). A ScreenGui with nothing to tap (the launch fade, the loading screen's backdrop) may use `None` to bleed to the edges. Found 2026-10-15: `Builder.screen` (`src/client/UI/Builder.luau`) sets `IgnoreGuiInset = true` and never sets `ScreenInsets`. Confirm in Studio what a notched phone gets from that pair, then set the property explicitly in `Builder.screen`.
- **Hit area: 44 px floor.** Roblox cites the W3C 9 x 9 mm touch target (about 57 logical px at 2x on an iPhone SE, per the report); guides say 44 x 44 px with a larger invisible hit area behind small icons. Ours is 44 px: a tappable face smaller than that gets an invisible `Active` hit area of at least 44 x 44 px centred on it, a ZIndex above any label it overlaps; the face keeps its look. The Shop price button's 26 px floor went with the old panel: on the shelf the pill stays a 32 px face at 667x375 and `Builder.button` takes `hit = true`, an invisible 44 px area over it (see [[#Shop shelf (2026-10-15)]]). Others to audit at the rebuild: the close X (80% of a header), the round top buttons, and the radar blips (a tap area twice a 9 px blip is about 19 px on the 93 px disc at 667x375; 44 px areas cannot fit there, so decide at the Radar rebuild, for example by taking the nearest blip within reach).
- **Preferred Text Size plan.** `GuiService.PreferredTextSize` (Medium by default, up to Largest) enlarges every label that has `TextScaled` off and no `UITextSizeConstraint`; developers report broken UI above Medium, and every fit measured in this Playbook assumes Medium.
  - Fixed boxes keep the measured 14 px floor and opt out of the setting: `TextScaled` on with a `UITextSizeConstraint` (min 14, max the role's size). `Builder.label`, `Builder.button` and the text box already do this, so chips, button faces, tile names and prices, toasts, bar text, the compass line, radar rows, tabs and reveal text do not move with the setting. A label built outside `Builder` with `TextScaled` off and no constraint is the one that breaks: audit for them. The Shop's about-line and tile descriptions are described above as `TextScaled` off at the 14 px floor; check whether they carry the constraint, because without it their measured bands clip above Medium.
  - Reading text honours the setting: descriptions and help over two lines, Field Notes and quest text, settings text, the Visitor Book, hint lines. `TextScaled` off, no constraint, in a band that scrolls or grows (`AutomaticSize` on Y) and is sized for Largest, not measured once at Medium.
  - A screen that clips at Largest gets a taller band or a constraint, never a smaller font.
- **Thumb zone.** Phone (landscape): the menu is a 2 by 3 cluster at the bottom-left, one prompt (the single contextual action) at the bottom centre, and nothing interactive in the top-left corner, which is Roblox's own menu and chat. Tablet: one column on the left, because "a button placed 40% below the screen's top edge is reachable on a phone but almost unreachable on a tablet" (Roblox, Position and size). Caveat from the same docs: keep important buttons out of the bottom corners where the thumbstick and the jump button live; the Build tray and the bottom banners already sit there. Before the HUD is rebuilt, check the cluster against `TouchGui` at 667x375 and 844x390 and move it up the left edge if they collide.
- **No stroke tween on text.** Never tween a `UIStroke`'s `Thickness` on a text object: the engine "renders and stores many glyph sizes each frame". Animate the holder (position, `UIScale`, transparency) and leave the text's stroke fixed. A search of `src/client` found one Thickness tween, the Star Chart planet pulse (`StarChartScreen`, `PULSE_SWELL`); check that it is not on text.
- **The event banner is a chip.** Under the ship bar sits a chip with the banner's content (icon, name, time left, the luck chip when luck changes), never a full-width bar on the eye line. It keeps the banner's slot in the centre column and its rules (one at a time; the Meteor Shower countdown and weather events share it). The 5:1 pill under "Event banner and compass" stays until the HUD is rebuilt from the canvas, then shrinks to the chip. The Shop's featured banner is another thing and keeps its width.
- **The reveal in three beats.** Built 2026-10-15: see [[#The reveal in three beats (2026-10-15)]] for the anatomy and the numbers. The genre's four (anticipation, rupture, identity, valuation) are on screen today as rupture, identity and valuation; what is missing is the first beat and the printed chance. The new reveal:
  1. **Taps to crack.** "Tap to crack!" with "One more!" progress dots; each tap does something (a harder shake, growth per tap, a sound). The server has decided the outcome before the first tap, so the taps are theatre: a Skip is always there and Reduced Motion goes straight to beat 3. Tap count, growth and durations are numbers in a data table under `src/shared/data`, set from the prototype's sliders (the day-7 Epic egg first).
  2. **Shards and rays in the rarity colour.** Polygon shards and a ray burst in the tier's colour from the standard rarity table, confetti scaled to the tier (Epic and above, as now). Particles do not render inside a `ViewportFrame`, so a reveal that shows the creature in a viewport draws the burst as 2D images around it.
  3. **The card with the chance.** Silhouette in a ring, then the creature, its name, the tier word in its colour and one line, "1 in N (x%)" (for example "1 in 33 (3%)"), read from the odds table that produced the creature and never typed into a string; the line is a keyed string in `src/shared/strings` with the numbers filled in. A percentage from the same table as the shown odds is also what the paid-random-item rules ask for.

  The base animation stays worth watching but never blocks the next action.
- **Device pass: four checks, not one.** The smallest phone (an iPhone SE profile in the Device Simulator, which accepts custom devices by width, height and pixel density); the largest tablet; a notched phone with insets confirmed; and the same screens with Text Size at Largest and Reduce Motion on. The HUD also gets a real low-end phone with the Developer Console open at graphics quality 3, since the emulator does not show memory.


## The reveal in three beats (2026-10-15)

Built from the research's reveal rules ([[#Phone rules from the design research (2026-10-15)]], "The reveal in three beats") and the rank ladder's "Catch and reveal" column ([[Roster-Redesign]] sections 1 and 6). Code: `src/client/UI/Reveal.luau`; every duration, count and size in `src/shared/data/Reveal.luau`; the pure half (lengths, per-tier scale, the chance line) in `src/shared/RevealMath.luau` with `tests/RevealMath.spec.luau`; `tools/lint_data.py` checks the table (`lint_reveal`, tests in `tools/tests/test_lint_reveal.py`). The server has decided the outcome before the first tap, so the taps are theatre, and nobody is ever stuck. Public API unchanged (`Reveal.Show`, `Reveal.Close`, `Reveal.IsOpen`), plus `Reveal.OnPlace(handler)` for the "Place it" button; `RevealInfo` gained `fromEgg` and `chancePercent`, both optional.

**Which path.** One code path for every reveal. A grant (an egg claim, a Peddler egg, a playtime egg, a quest or event alien, the Starter Pack's Rare) sets `fromEgg = true` and plays all three beats. A wild catch has no egg or capsule anywhere in today's flow (the capture bar goes straight to the card), so beat 1 is skipped and it starts at the shards; `CatchCrack = true` in the data gives it a capsule to crack, drawn and cracked exactly like the egg. Reduced Motion plays one still frame and then the whole card.

**Beat 1, Crack** (egg grants; 0.75 s authored: 3 taps of 0.25 s).
- An egg (a cream capsule: `Builder.frame` with a pill corner, gradient, gloss and speckles, 0.5 of the screen high at aspect 0.8) sits at 0.47 of the height with a white tap ring that breathes (1.0 to 1.07 in 0.7 s). "Tap to crack it!" (`REVEAL_CRACK`) is outlined, 30 px at the 375 px reference height (a 0.08 box, growing with the screen up to 48), at y 0.84; three dots at y 0.925 (17 px) show the taps (gold when tapped, a pop each).
- Each tap: a tick (`Sounds.CrackTick`, the wheel's tick id until the sound pass), a crack line (a zig-zag of three thin rotated bars, rows of `CrackLines`), a wobble that grows from 4 to 10 degrees (out, back past the middle, home, in 0.25 s) with a 1.06 squeeze, and the tier colour leaks from behind the egg: two discs (a soft edge) at transparency 0.92 before any tap, 0.55 after the last. The leak shows the colour, never the name. For a Secret the accent (purple) leaks, because 111111 is invisible on the dim.
- The server's answer is already in: `AutoCrackSeconds` (4) without a tap and the rest of the taps play themselves, one every 0.25 s; every tap restarts that timer. The 3rd tap hands over to beat 2 when its wobble ends. Taps past the third do nothing.

**Beat 2, Shards** (0.4 s of shards, then 0.6 s of rays or iris, times the tier's scale).
- At the burst: the egg is gone, six shards (tall thin pieces with the navy outline, cream from an egg, the tier colour from a catch) fly 0.3 of the height out, spinning, and fade; the glow flashes to 0.35 and eases to 0.55; the tier's stinger plays through `MusicDirector.Stinger` (the bed ducks for its length); the tier word drops in big (`REVEAL_WORD_<tier>`, "EPIC!", 64 px at the reference, 0.9 of the width, a heavy 4 px outline, Back ease in 0.3 s) in the tier colour; confetti for Epic and above (20, times the scale); the whole stage pushes in to 1.06.
- After the shards the rays spin up in the tier colour: a ring of 8 thin bars (16 rays) fades from clear to 0.55 while it turns 120 degrees (Quad out), then keeps turning once in 12 s (`Config.VfxRevealRaysSeconds`) behind the card. The Shine sprite (`Icons.Particles.Shine`) joins when it is uploaded. Under Reduced Motion the ring is static.
- **The ladder** (`data/Reveal` `Tiers`, one row per tier of `data/Tiers` Order; `lint_data` keeps it in step): Common and Uncommon have no rays (the ladder says "no rays", "a two-note squeak"), so their beat is the shards only. Rare turns the rays. Epic adds the confetti. Legendary and above are Grand: the whole shard beat is 1.8 times as long and the shards 1.8 times as big and far, the confetti 1.8 times as many, and the gold ground ring sits under the model on the card. Cosmic's rays alternate the tier pink and a second colour (`Select`, the sky blue). Secret has no rays: the screen dims a further 25% and a dark iris (a black disc with a purple rim) opens from a point behind the card.
- **Skip.** A tap during the shards jumps to the card (`Skip = true`); a tap within 0.2 s of a beat starting (`SkipGuardSeconds`) is ignored, so the tap that cracked the egg cannot also skip.

**Beat 3, the card.**
- The existing card (rendered creature, NEW! ribbon, name, tier row, overlay badge, size stamp) drops in from 0.6 of the height above with a Back ease (0.35 s). Then, from the landing: at +0.1 s the chance line, at +0.25 s the chips (the size stamp and its multiplier, the Perfect line, the Storage-full ribbon), at +0.45 s the two buttons slide up (0.3 s Back ease), all inside the 0.8 s hold. The "+N Scrap" float and a Perfect flash start at the landing. "Tap anywhere to continue" (`REVEAL_TAP`) shows when the buttons are up; a tap before that finishes the entrance in one go (and a tap right after is ignored for 0.2 s), a tap after closes.
- **The chance line**: "1 in N · x% chance" (`REVEAL_ODDS`, `RevealMath.OddsLine`). N is 100 over the percent, rounded, at least 2, with thousands commas; the percent has one decimal from 1% up, two below, trailing zeros trimmed ("6%", "12.5%", "0.25%"). It is a navy pill with a white rim in the tier colour, hung on the card's bottom edge, 1.5 card widths wide, because the card is only 168 px across at 667x375. **Where the number comes from, never typed**: for an egg, the server's own draw (`GrantResult.oddsPercent`, set by `Peddler` and `Gifts` from `EggMath.Percent` over the pool it drew from: 100 over the number of species the egg could hatch); for a wild catch, the tier's spawn share in `data/Tiers` (`RevealMath.SpawnPercent`; Cosmic and Secret have none outside a shower or a quest, so no line); for any other grant (a fixed quest or event alien, the Starter Pack), nothing, and the line is hidden. A percent of 0, under 0.01, 100 or more, or not a number also hides it.
- **The buttons**: "Place it" (green; closes the Reveal and calls the handler `Reveal.OnPlace` registered, which the bootstrap points at `Screens.Open("Aliens")`; hidden when no handler is registered or when the alien overflowed into Scrap, so no tap is silent and nothing is offered that cannot be done) bottom left, "Keep going" (blue; closes) bottom right. 52 px tall at the reference height (0.139 of the screen, a 46.8 px face over the 44 px floor, plus `hit = true`, an invisible 44 px area), 0.24 of the width (160 px) each, 0.03 from the edges; the footer takes the 0.46 between them and is two lines tall, for a portrait phone. The recommendation to keep important buttons out of the bottom corners is about the HUD, where the thumbstick and jump live; the Reveal is a modal with no thumbstick in play.

**Toasts wait.** `Toast.Hush()` at the start of beat 1 (the first thing `Reveal.Show` does after setting `open`), then `Toast.QuietFor(RevealMath.QuietTotal(...))`: the sequence for the tier plus `QuietSeconds` (2), computed from the data: a Rare egg is 2.9 + 2 = 4.9 s. The sky's twinkle and the frame's chase are the only motion that lasts; job 38 measures the frame rate on a phone during a Cosmic reveal.

|---|---|
| A rarer tier adds something new at the hero beat, and keeps everything the tier below has | A rare reveal that is the common one in another colour |
| Square cells and stepped pixel shapes for every burst, ring and ray | A round glow, a soft radial gradient, a rotated thin bar |
| Grow or step a group of cells as one (a UIScale, a band at a time) | A tween on each of a hundred cells |
| The tier's colour as the card's ink | A stroke round the card |

## Block cells (2026-10-21)

Ethan, 2026-10-17: "make that consistent throughout the whole game" ([[Decisions]] B44); [[Decide-Now]] 43 taken **a** on 2026-10-20 (B46): the UI in block cells, one screen per change, HUD first, because a rounded glossy HUD over a block-cell world reads as two games. The approved board is "HUD in block cells" on the [Catch an Alien UI canvas](https://claude.ai/artifact/GsddVfW4nSoBSRpEpCSvi4), beside the phone HUD it replaces. The cell rules are the creatures' and the world's ([[Blocky-Style]] C1 to C6), applied to flat UI. Code: the helpers in `src/client/UI/Builder.luau` (section "Block cells"), the arithmetic in `src/shared/BlockMath.luau` (`tests/BlockMath.spec.luau`), the tokens in `Theme.Block`, the icons in `src/shared/data/PixelIcons.luau`. First screen: the HUD (`src/client/UI/Hud.luau`). Test steps: `docs/TESTING.md` "HUD in block cells"; the Mac check is [[Overnight]] job 36.

**A plate** (`Builder.blockPlate`)
- **Whole square cells.** A plate is `rows` by `cols` cells. The rows come from its height: round(height / `Theme.Block.Cell` - 2 x ink), at least `MinRows` (3), with `Cell` 0.02 of the screen height (the board's 8 px at 390 tall); the columns are the whole number nearest square cells for the plate's aspect (C1: every face a whole number of cells, no sliver). The plate keeps its aspect with a `UIAspectRatioConstraint`, so the cells stay square on any screen (within 6% on every HUD plate).
- **Stepped pixel corner.** The four corner cells are cut away; the navy ink border (`Ink` 0.4 of a cell) runs round the notched shape at one thickness, the step too. Built from frames: two overlapping bars for the ink and two for the face. No `UICorner`, no `UIStroke` on a block, no image, so nothing waits on an upload and nothing breaks at an id of 0.
- **Lit top, shaded edges (C3).** The top row a step lighter (white at `TopAlpha` 0.7 transparency), the bottom row and both side columns a step darker (black at `EdgeAlpha` 0.8), without the cut corners, and only on a plate three cells or more both ways.
- **Grout (C3).** A line an eighth of a cell thick (`Grout`, one texel at eight texels a cell) on each cell's right and bottom edge, black at `GroutAlpha` 0.9; none along the ink, and the first lines skip the cut corners.
- **Jitter (C2).** A hash of each cell's grid position and seed 44 (`BlockMath.Level`): one cell in eight a shade down, one in eight a shade up (black or white at `JitterAlpha` 0.9), the rest level. Deterministic: the same plate every build. `seed` on the props gives a neighbour a different scatter.
- **Recolour.** All shading is white and black overlays over the "Fill" frames, so `Builder.setBlockColor(plate, colour, tweenInfo?)` recolours a plate by its Fill frames alone (the clock's day and night, the Friend chip going green).
- **Layers.** Inside a plate, above its own ZIndex: ink +0, face +1, a bar +2, the cell overlays +3, content +4. Put labels and icons at `Builder.blockTop(plate)` or higher, or the overlays wash over them.
- **Flat block** (`cells = false`): ink, face and the stepped corners only, for a small detail (C3: "a smaller detail block stays one flat colour"): the badges, the banner's luck chip, an icon square's placeholder.

**A button** (`Builder.blockButton`, same props as `Builder.button` plus `rows`)
- A block-plate face over a flat lip exactly one cell deep in the colour darkened (`Theme.Darken`), so the button stands on its own shadow. A press **sinks the face one cell** onto the lip (no 0.92 squash: blocks do not squash); a hover on a mouse grows it to `Theme.Block.Hover` (1.04); every tap plays the click; `hit = true` adds the invisible 44 px area as on `Builder.button`.
- Text: white Fredoka One with the navy outline (`Builder.stroke`, so it scales with the screen height), padded half a cell sideways and a quarter cell top and bottom inside the ink. An icon replaces the text: the pixel icon at 0.8 of the padded box (about 0.6 of the face).
- Returns the container: "Face" is the `TextButton` (set its `Text`), "Plate" and "Lip" are plates. `Builder.restyleBlockButton(container, text, colour, enabled)` is the block twin of `Builder.restyleButton`. Rows: from `size.Y` as a Scale of the screen, less the lip (`Builder.blockButtonRows`); pass `rows` when the button's size is a fraction of something other than the screen (the menu slot does).

**A bar** (`Builder.blockBar(plate, colour)` returns a setter, 0 to 1): the fill runs across the face from the left in two frames that keep the stepped corners (a sliver under one cell lights only the middle rows), under the cell overlays so the fill reads in cells too. `Builder.blockInner(plate)` gives the face's inner box for the tick marks. The ship bar tweens a `NumberValue` and the setter follows it.

**Pixel icons** (`Builder.pixelIcon`, `Builder.blockIcon`, `data/PixelIcons`): an icon is rectangles on an 8 by 8 grid (`Theme.Block.PixelGrid`), `{ x, y, w, h, colour }`, the colour a `Theme.Colors` key or a hex string, drawn in order as frames in a square holder. Drawn from the board: Scrap, Shower, Ranks, Settings, Shop, Aliens, Codex, Ship, Quests and Gifts; Playtime (an hourglass) was drawn to match. Drawn to match on 2026-10-21: the six power-ups (SpeedBurst a gold bolt, SteadyHands a bullseye, ScannerPulse a radar screen, LuckyCharm a four-leaf clover, ScrapMagnet a red horseshoe magnet, DoubleShift a gold-rimmed clock), the three lures (a line, a body and a hook: a brown twig, a blue body with a white core, a gold star) and the eggs (`Egg`, and `Egg<Tier>` speckled in the tier's rarity colour). - **Fitted plates.** A box whose shape changes with the screen (a band a share of the width and the height, a row in a list, a button in a row of buttons) has no aspect to keep, and an aspect constraint would move the layout. `Builder.blockPlate` and `Builder.blockButton` with no `aspect` make a fitted plate: no constraint, the plate measures its px box and draws the whole number of columns nearest square cells for it (within 6% of square from nine columns), again only when that number changes. Its rows are `rows` (or picked once from its height as a share of the screen). A panel opening scales both sides alike, so it never redraws mid-tween; a rotation or a resize may. A recolour (`setBlockColor`) and a bar (`blockBar`) survive a redraw.
- **Thin bands are flat.** A plate under 0.05 of the screen tall is three rows of cells under 4.5 px at iPhone SE: all edge, no face, and its grout would be half a pixel. It is a flat block (`cells = false`), like a badge: the compass strip (15 px at SE, 3.9 px cells) and its heading block.
- **Pixel shapes, not turned squares.** A marker that was a square turned 45 degrees is a stepped pixel diamond on the 8 by 8 grid, overlapping bars (four of ink, three of colour one unit inside), so its ink keeps one thickness round each step: seven frames, no stroke, no rotation.
