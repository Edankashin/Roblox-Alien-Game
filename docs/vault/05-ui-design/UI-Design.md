# UI design

How the game's screens look and behave. Back to [[Start-Here]].

- [[UI-Playbook]]: the look written to the level Claude can build from: font, palette, panels, buttons, rarity colours, every screen's recipe. Read it before any UI work and update it in the same change when a review corrects a panel.
- [[Claude-Design-Brief]]: how the team uses Claude Design (the in-chat canvas): what it is for (mockups, species sheets, thumbnail comps, the hatch prototype), what it is not for (meshes, shipped UI, raster icons), the workflow and the prompt patterns. Read it before opening a Design session.
- [[Clean-UI-Pass]]: the declutter spec of 2026-10-22 (principles with sources, the on-screen inventory, the notification budget, the first five minutes, three parallel work packages). Read it before touching the HUD, toasts, banners or a panel's layout.
- [[UI-Richness-Pass]]: the richness spec of 2026-10-26 (TikTok ZPLAVdpnX): one panel anatomy (band, pills, tinted body, sections, tile states, tier frames), world cards, featured-plus-grid, the goal card with bar and reward, the arrival title card, and three work packages. It builds on the Clean pass; read it before touching a panel's header, the Star Chart, Aliens or Codex.
- [[UI-Checklist]]: the checks every screen passes before it ships (Scale only, iPhone SE and iPad, touch targets, strokes, a tween and a sound on every tap). Run it last.
- [[05-ui-design/refs/README|Reference screenshots]]: the cropped frames from the reference videos (stud and wood dialects) and the renders in `refs/look-l1`, `look-l3` and `look-l5`. Open it when a review asks "like which game?".
- [[UI-Rules]] (kept with [[Roblox-Engine]]): the engine-side rules the playbook assumes.
