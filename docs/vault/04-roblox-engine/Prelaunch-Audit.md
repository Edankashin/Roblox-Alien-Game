# Pre-launch audit (2026-10-21)

A source audit before the public launch ([[Decisions]] B49, [[Launch-Dashboard]] "Launch week"). It covers server authority and exploits, saves, purchases, a cold server with no uploaded assets, text and UI, analytics and limits, and moderation and policy. The game's design was not changed. Read the code, ran `tools/lint_remotes.py`, the headless specs, strict analysis and the lints. Nothing was run in Studio: the checks only Studio can do are Mac job 46 (TESTING "Pre-launch audit"). It builds on [[Exploit-Review]] (the 60 handlers and decisions D1 to D8) and [[Performance]].

Severity: **High** means a player could get a paid item free or lose access to their save. **Medium** means a likely loss of data or Robux, or a broken promise in the shop. **Low** means wrong numbers or a cosmetic leak. **Info** means checked and fine.

## Findings

| # | Sev | Finding | Fix |
| --- | --- | --- | --- |
| 1 | High | A finished pass prompt granted the pass from `PromptGamePassPurchaseFinished`'s `wasPurchased`. That flag comes from the client's prompt, so it is not proof of a purchase. A forged signal could hand out +1 or +2 slots on every station, the Explorer Pack gear or the other passes for free. | `d1b2260`: `Monetization.confirmPass` asks `UserOwnsGamePassAsync` first (retried `Config.PassCheckRetries` times). A failed lookup grants nothing now, and the next join's pass check applies the grants. Studio trusts the signal, because a Studio test purchase is never really owned. |
| 2 | High | A player who left while their profile was loading kept the save locked. `PlayerRemoving` found no profile, then the load finished and kept the lock for `SessionLockSeconds` (600 s). Rejoining within 10 minutes meant waiting 30 s and then being kicked with "locked". | `afc64b2`: when the load finishes after the player left, the lock is released at once (`PlayerData.release`). |
| 3 | Med | A DataStore error at join kicked the player at once. Only a held lock was retried. | `afc64b2`: every error except a save from a newer version is retried `Config.LoadRetries` times, `LoadRetrySeconds` apart. |
| 4 | Med | The leave save and the shutdown save were tried once each. During a shutdown, `PlayerRemoving` and `BindToClose` both wrote the same key in parallel. A receipt's `SaveNow` landing during a leave could lock the key again. | `afc64b2`: one release per player at a time, retried `Config.ReleaseSaveRetries` times with the wait doubling from `ReleaseSaveRetrySeconds`. A save that runs during a release writes no lock. A rejoin to the same server is not dropped by a late release. |
| 5 | Med | Two `ProcessReceipt` calls for the same PurchaseId could both grant while the first was still waiting on a granter or on the save. | `d1b2260`: `receiptsInFlight` makes the second call answer `NotProcessedYet`. Roblox asks again later, and the saved receipt id then decides. |
| 6 | Med | DirectRare, DirectEpic, AutoCollect, ModuleRush and RadarMk1Unlock have no `Shop.Grants` row because their features are not built. The Launch-Dashboard asked Ethan to create them on the dashboard. Once an id was pasted, a receipt would have recorded a purchase and granted nothing (a client can prompt any product of its own game). | `d1b2260`: the server sells only items that are live and have a grant row (`ShelfMath.IsSellable`, specs). Any other live id gets a boot warning, and its receipt stays `NotProcessedYet`. Launch-Dashboard now says to skip the five. |
| 7 | Med | **Paid spins pay things that are "never sold"**: Spins1, Spins5 and Spins12 (Robux) spin the same wheel as the free spins. That wheel pays 200, 600 or 2,000 Scrap, a Lucky Charm or a Double Shift. `data/Shop.NeverSold` lists all three, and CLAUDE.md says Scrap is never sold for Robux. | **Not fixed: a design decision for Ethan.** Options: (a) give paid spins their own wheel without Scrap, Lucky Charm or Double Shift, with odds that still sum to 100; (b) accept random Scrap from a paid spin and reword the rule; (c) hide the three spin products at launch (set their ids aside). The odds are shown, sum to 100 and have no dud either way. |
| 8 | Low | The onboarding funnel used the recurring funnel call (`LogFunnelStepEvent` with no session id). Every returning player sent the steps they had already passed again in each session, which inflated the early steps. | `bdb6455`: `LogOnboardingFunnelStepEvent`, counted once per user. Check the Creator Hub funnel on day 1. |
| 9 | Low | Studio multi-client test players (UserId 0 or less) would write rows with no name to the live weekly board, because Studio uses the real stores (`Config.UseDataStoreInStudio`). | `d9767ef`: those ids are counted locally only. Ethan's own Studio play still counts on the live board (`/lb` adds catches to it too). The board resets on Friday at 16:00 UTC. |
| 10 | Low | A Robux card with id 0 in a Launch section showed a grey SOON pill. None of the five id-0 items is in a Launch section today, so this never happened. | `095abdf`: such a card is hidden, and so is its tab when nothing else is in it. |
| 11 | Info | Every one of the 67 incoming handlers calls `Net.allow` (`lint_remotes`: clean). Six were added after [[Exploit-Review]]: BuyStorageBay, ClaimPlaytimeGift, GetPlaytime, MarkSeen, ReleaseAliens and ReleaseAllOfTier. Each has type, range or enum checks, a rate limit, own-profile writes and all-or-nothing debits. No grant uses a value the client sent. | Safe. |
| 12 | Info | The new client world code (Spectacle, WorldFx, RigAnimator, SpeciesFx, wild wander) sends nothing to the server. The only client calls in `src/client/World` are the read-only GetPeddler and GetAllCompanions. | Safe. |
| 13 | Info | Dev commands are registered only under `RunService:IsStudio()`, so none exists in a live server. `/admin` checks `Admin.DeveloperUserIds` on every command and on every message it receives, with a 30 s replay guard and 6 commands a minute. Its `say` and `mail` text is filtered. | Safe. |
| 14 | Info | Saves: one key `User_<id>`, `UpdateAsync` everywhere, a session lock, schema v18 with migrations and refusal of a save from the future, 180 s autosave, a 25 s `BindToClose` window. This week added no profile field (spectacle and worlds are data and client only), so no migration is needed. A receipt answers Granted only after `SaveNow` (D8). | Safe after fixes 2 to 4. |
| 15 | Info | Policy: `GetPolicyInfoForPlayerAsync` is cached per player. A failed lookup counts as restricted and is not cached. Paid random items (Server Luck, Spins) stay hidden until the client hears the policy, and the server refuses `PromptPurchase` with `Restricted`. The wheel odds sum to 100 and have no dud. No eggs are sold for Robux. | Safe. |
| 16 | Info | Cold start: every asset path checks for id 0 before building (`Meadow` tiles, `Builder.icon` and the sounds, `EffectsMath.SpriteFor`, Reveal, WildRenderer, RigAnimator, WorldFx, WeatherFx, Vfx, MusicDirector, Ambience, Spectacle). The model loader waits at most `ModelLoadTimeoutSeconds` (20 s). The loading screen fades out on `ClientStarted` and removes itself after 25 s whatever happens. | Studio: job 46 times a fresh join. |
| 17 | Info | Text and UI: `lint_strings`, `lint_ui` and the 14 px specs (BlockMath, BadgeFit, the screen specs) pass. One advisory silent tap remains (the CaptureBar backdrop, which has no handler on purpose). | Safe. |
| 18 | Info | Limits: 8 autosaves every 180 s, one leaderboard increment per player per 60 s, and one `GetSortedAsync` per server per 60 s. No DataStore or MessagingService call sits in a loop without a wait, and MessagingService is used by `/admin` only. That is far under budget at 8 players, so `GetRequestBudgetForRequestType` is not needed. | Safe. |
| 19 | Info | Moderation: no line crosses servers apart from `/admin` (filtered). The server banners show Roblox DisplayNames. No cross-server Secret line exists in code, so it shows no username. [[STORE-PAGE]] section 3's questionnaire answers still hold. Section 6's stale lines are updated. | Safe. |
| 20 | Info | Performance to measure: once its tiles are uploaded, World 1's generated ground is 4,255 parts, 3,072 placeholder parts and 10,222 Texture instances, all built on the server at boot. `Workspace.StreamingEnabled` is not set in `default.project.json`. | Studio: jobs 43 and 46 measure join time and memory at iPhone SE. Check StreamingEnabled in the published place. |
| 21 | Low | Mac job 46 saw `ContentId: rbxassetid://203785492 failed due to: Asset type does not match requested type` on every Play (and "Failed to load sound rbxassetid://203785492" in an earlier run). Checked 2026-10-26: **the id is in no file of the repo** (src, data, the four `asset_ids.json`, tools, assets), so it is not one of ours and not a Decal-versus-Image mix-up in the tables. It is loaded as a Sound, so it is a Sound, or a thing wearing a Sound, in the place file (an old Toolbox model, a template leftover), the avatar's gear or a Studio plugin. | Lint: `tools/lint_data.py` now refuses any id used under two asset types ([[Data-Lint]]). Finder: `tools/studio/find_asset.luau` prints the full path of every instance naming an id (Mac job 71 runs it, in Edit and in Play; delete or fix the instance it names in the place, which the repo cannot do). |
