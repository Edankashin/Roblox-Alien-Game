# Save size budget

Generated by `python3 -I tools/save_budget.py --write` (override `--hours-per-day`, `--storage-cap`, `--receipt-cap`, `--stack-share`).

Inputs: ProfileSchema template, Types.Profile, all live data tables and balance.py. SHA-256 input fingerprint `2064e4aacd57364f`. [[Testing-Headless]] · [[Exploit-Review]].

[Roblox documents a 4,194,304-byte per-key limit and JSONEncode measurement](https://create.roblox.com/docs/cloud-services/data-stores/error-codes-and-limits). Compact UTF-8 JSON is modeled here; nil keys are omitted, dense arrays are arrays, dictionaries are objects. Empty arrays versus objects cost the same two bytes. Runtime float formatting/Unicode text can differ: validate with JSONEncode before setting a production safety margin.

Three seeded balance.py progression runs yield median **289.96 successful grants/hour** (includes progression gifts); fusion consumes **86.8%** of grants in that short progression sample. Main scenario retains every catch: fusion is optional, and extrapolating the short sample’s fusion fraction for a year is not a guarantee. No paid catches, search slowdown or future catalog additions are invented.

Reconstructed fresh template: **1,216 bytes**. Heavy fixed reserve: **16,626 bytes**, filling current codex, house caps (conservative even if footprints cannot coexist), mailbox, visitor book, receipt cap and current season tracks; other template fields remain initial. This is a scoped estimate, not a worst-case proof. Alien examples use the longest current species id `Shimmerlynx`, a 36-character UID both as key and in the record, a ten-digit timestamp, level 1, Normal/None, no optional assignment. Assignments, grown workedSeconds, longer overlays and other accumulated fields increase bytes.

Release prices require a coordinator decision; no economy values are proposed or applied. Stacking requires redesigning UID references, caughtAt and workedSeconds semantics and excluding seated/following/displayed/unique copies. The stack share is an explicit scenario assumption, not measured prevalence. Pruning receipts already exists: shrinking the replay memory risks duplicate grants; no time-based guarantee is established by the code comment. Finished tracks need a durable claimed marker if an event returns.
