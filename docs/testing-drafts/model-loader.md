## Runtime model loader (World 1 place, then a fresh baseplate)

The 53 species and prop meshes used to exist only inside the Studio place files, installed by hand with `tools/studio/install_models.luau`; a place built from the repo (`tools/publish.py`) had none of them and showed placeholder shapes. The server service `Services/Models` now loads them at boot from their uploaded asset ids (`data/ModelAssets`, generated from `assets/models/asset_ids.json`) with `InsertService:LoadAsset`, so a Rojo-built place has every model and publishing needs no Studio. It runs right before Meadow in the boot order (Meadow places the scenery props at Init), waits at most `Config.ModelLoadTimeoutSeconds` (20) for the loads, keeps at most `Config.ModelLoadConcurrency` (8) in flight at once, and keeps loading late arrivals after the wait. A name whose folder already holds a Model of that name (the hand-installed ones) is counted present and skipped, so a Studio place with the models installed loads nothing. The colours, material choice, part renaming and anchoring are the installer's rules, shared as `Shared/ModelInstall` (headless spec `ModelInstall.spec.luau`). `LoadAsset` only loads assets the experience's owner owns, so run steps 2 to 5 in a Studio signed in as that owner. Dev: `/models` prints the counts and the failed names, `/models retry` loads the failed ones again.

1. Nothing changes where the models are installed. Play in the connected World 1 place (the one with the models installed by hand). Output has `[AlienGame] Models: 0 loaded, 53 present, 0 failed, 0 pending after 0.0 s` before the `Meadow` line, no `Models:` warning, and the meadow, the trees, the rocks and the aliens look exactly as before.
2. A fresh place loads everything. Make a new empty Baseplate place, sync it with `rojo serve default.project.json`, check that `ReplicatedStorage.Models` does not exist, and Play. The boot line reads about `Models: 53 loaded, 0 present, 0 failed, 0 pending after N s`, with N under the 20-second timeout (a slow connection may read some pending; wait a few seconds and run `/models`). Afterwards `ReplicatedStorage.Models` holds 32 creature Models and `ReplicatedStorage.Models.Props` holds 21. Open `Models.Mossbop`: its parts are coloured (green body) and named Body, EyeWhite, Pupil, Mouth, BodyDark, Accessory, EyeHighlight, every part Anchored with CanCollide and CanQuery off. The meadow trees and rocks are meshes, not the part-built placeholders, and `/spawn Mossbop` shows the Mossbop mesh in the meadow, not a placeholder shape.
3. The command agrees. In the same session `/models`: Output `dev: models 53 loaded, 0 present, 0 failed, 0 pending` and no failed line.
4. The switch works. Set `LoadModelsAtBoot = false` in `src/shared/data/Config.luau` (Rojo syncs it; put `true` back afterwards), stop and Play in the fresh baseplate again: Output has one line `Models: runtime loading is off (Config.LoadModelsAtBoot) ...`, `ReplicatedStorage.Models` does not exist, the meadow shows the placeholder trees and rocks, and `/spawn Mossbop` shows the placeholder alien.
5. A failure is named and can be retried. In a scratch copy of the repo (or temporarily, then undo it), change one asset id in `src/shared/data/ModelAssets.luau`, for example Mossbop's, to `1`, and Play in the fresh baseplate. The boot line reads `Models: 52 loaded, 0 present, 1 failed, 0 pending after N s`, followed by a warning naming Mossbop, its first error text and the moderation hint (a just-uploaded asset can be in moderation for a few hours); `Models.Mossbop` does not exist and `/spawn Mossbop` shows the placeholder alien while every other species is a mesh. `/models`: Output `dev: models 52 loaded, 0 present, 1 failed, 0 pending` and `dev: models failed: Mossbop`. `/models retry`: Output `dev: models retry queued 1`, then the loader's own line again with `1 failed` (the id is still 1, so it fails again).

Known gaps in this milestone: the world is built only after the loads finish or the timeout passes, so a hung asset delays the boot by up to 20 seconds; a model that arrives after the timeout is used by later spawns and the next server, not by props the meadow already placed; a collaborator's Studio may fail every load with a permission error and fall back to placeholders; the Studio installer `tools/studio/install_models.luau` still carries its own copy of the rules (it can take `Shared/ModelInstall` later).
