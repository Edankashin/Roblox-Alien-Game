## Security decisions D1, D4, D6 (World 1 place)

Three decisions from the exploit review (`docs/vault/04-roblox-engine/Exploit-Review.md`), implemented in source: capture timing is watched, not refused (D1); a catch, pickup, module payment or heater is refused while a launch or flight is in progress (D4, `src/server/Flight.luau`); a season claim delivers its aliens first and pays nothing if an alien is refused (D6). Nothing here has been run in Studio yet.
1. D1, capture timing telemetry: hitting Perfect on nearly every one of 40 taps by hand is impractical, so the check is the code path (`Catching.tallyTap`) and the spec (`tests/Capture.spec.luau`, the `suspect` cases). In Studio: `/spawn Mossbop` and catch a few aliens, mixing Perfect, Good and Miss taps. Output shows no `SuspectTiming` event line and no warning, and catching behaves exactly as before. Optional, to see the log line: in a scratch copy set `Config.SuspectPerfectRate` to 0, tap 40 times (any outcome); Output then prints `analytics: event SuspectTiming value=<percent> window=40 (<your name>)` and a warning "hit Perfect on <percent>% of their last 40 taps", once, and the count starts over. Put the value back.
2. D4, launch: `/spawn Mossbop` near the ship, `/complete`, walk to the ship and press Launch. During the lift and fade (5.5 s, `Config.LaunchTeleportDelaySeconds`) tap the wild alien and then a material node: no capture bar opens and nothing is picked up; the toast "Hold on, your ship is taking off" shows each time (a catch tap also prints `capture refused: InFlight` in the client Output). A second Launch press still answers Busy, as before. After the view returns (Studio skips the teleport and the latch clears when the delay ends), catching and picking up work again. Ship screen Pay and Insert Key and the Heater button are refused with the same reason during a flight; the Ship screen only prints `ModulePay refused: InFlight` (no toast yet, see the review's open note), and a Heater needs the World 2 place in a blizzard.
3. D4, Star Chart flight: with a world unlocked other than the one the profile is on (after step 2 the profile says World 2), open the Star Chart, pick World 1 and press Fly. During the fade (1.5 s, `Config.FlyTeleportDelaySeconds`) repeat the catch and pickup taps: same refusals and the same toast; a second Fly answers Busy. After the fade the latch clears and both work again.
4. D6, season claim: `/season HauntedNebula`, `/season done`, open the Quests screen's Event tab. Claim the first row: toast "Claimed: 500 Scrap", Scrap +500, the row reads Done (unchanged). Claim the last row (Nebulyn): the Reveal shows Nebulyn and it joins the camp. To see the refusal path, on a profile whose last row is still unclaimed (a fresh one, or before claiming it above), change the last row's alien id in a scratch copy of `src/shared/data/Seasons.luau` to a species that does not exist (for example `NoSuchAlien`; `python3 -I tools/lint_data.py` rejects it, so revert afterwards), `/season done` and claim that row: nothing is paid, the tap answers Refused (Output `ClaimSeasonQuest refused: Refused` and the server warning "alien NoSuchAlien was not granted, so the claim is taken back and nothing is paid"), and the row stays claimable: its Claim button is still lit and a second tap gives the same answer. No quest pays an alien plus other rows today, so the case "aliens delivered, Scrap rows refused" (claim stays marked) has no hand test; it is the second branch in `Seasons.onClaim`.

Known gaps: the Ship screen shows no toast for an `InFlight` refusal of `ModulePay` or `ModuleInsertKey` (the screen file was outside this change); speed and teleport validation of the character was not added (range checks against the replicated character stay).
